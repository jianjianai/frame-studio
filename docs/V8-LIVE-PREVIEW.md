# V8 实时预览

Frame Studio 8.0 将编辑播放与正式编码分开。创作页的更新来自持续监听当前作品或 AI 隔离草稿的源码会话。改一行代码、调整音量或改动片段，不再创建完整 build 任务。正式成片仍由原有离线导出流程编码和验证；旧的不可变预览与历史版本继续可用。

## 使用

创作页自动选择当前作品或活动 AI 草稿，在同一个播放器内更新。更新按钮重新连接和同步实时会话。代码错误或场景初始化失败保留最后成功画面并显示错误；修好后自动恢复。断网后按退避重连，重新获取最新尚未应用的版本。

远程工具 `frame_works_live_preview` / 平台操作 `works_live_preview` 接受：

```json
{ "id": "作品 UUID", "task": "可选的当前作品 AI 任务 UUID", "ai": true }
```

返回会话 UUID、能力链接、源码哈希、来源、状态和到期时间。AI 任务内 `node scripts/work-tool.mjs preview` 无参数打开已授权的作品与草稿。默认 `works_browser` 使用实时预览；显式 `mode:"snapshot"` 或 `rebuild:true` 使用原有不可变构建。历史版本审阅不切换为实时工作目录。

源码监听在服务端执行常驻增量打包，客户端收到更新清单后才导入必要的带内容哈希模块。Three、Tone、React 等未改变的依赖复用浏览器缓存；JS/CSS 提供 Brotli/gzip。持续更新连接只传状态和版本信息。能力链接只能读取此会话的编译产物及所属作品公开素材，不提供源码文件、凭据或其他工程的读取入口。

## 画面与声音更新

候选场景先在隐藏画布或 DOM 中准备当前时间的第一帧，成功后一次切换。失败释放候选，上一版本继续可用。快速连续保存合并到最新版本；差异相对实际已应用版本计算，避免丢失期间的音频变化。

播放器保留位置、播放/暂停、速率、循环、静音、音量和选段。只改画面保留 Frame 音轨的同一个 AudioContext 与音频调度；音量和处理器参数平滑更新；片段或声音源变化只重建有关声音。场景和声音共用播放时钟。视频读取、生成器准备和声音缓冲不足会暂停共同时钟，恢复后从同一点继续。

Remotion 组件音频继续由其原生播放器管理，候选准备期间旧场景保持播放；接受更新后组件跟随公共时间轴，旧播放器暂停并释放 DOM；已退休上下文的迟到恢复会再次暂停，避免旧场景继续运行。Frame 音轨的上下文独立保留。Remotion 使用 Frame 的初始音量与静音设置，隔离预览不访问 localStorage。

V7 `audio.json`、旧 `audioTracks` 和 `createAudio` 生成器直接进入实时调度。生成器应支持绝对时间和局部调度，并释放所拥有的资源。实时播放不运行完整影片的音频采样、FFmpeg 混音或 2 秒切块。改生成器源码时版本键更新，生成器和缓存按引用释放。

## 高延迟与慢网络

- 媒体 URL 绑定文件内容 SHA-256。相同文件复制或重新发布不会失效缓存，原路径被替换不会改变已显示版本的素材。
- 音频共享版本缓存，限制请求并发、队列和内存；预取按实际吞吐和网络状态调整。较大的未压缩音频使用缓存 AAC 预览代理；MP3、AAC 等压缩音轨的标准播放复用原素材，慢网络可选择 48 kb/s economy 副本。离线混音使用原始素材。
- 视频支持 HTTP Range、共享解码输入、顺序帧迭代和相邻帧缓存。压缩缓存与解码帧预算为全局上限，跨热更新共享。取消一次绘制只取消该次等待，其他场景持有的媒体仍可用。
- 视频草稿和标准预览可以使用缓存的低码率 H.264 代理；`high` 质量使用已冻结原文件。合成场景自动传递质量；自定义场景使用 `openVideoSource(src, width, signal, options.quality)`。
- 大图片使用按质量缓存的缩小 WebP 副本，并保留透明度；SVG、动画图片和小文件保留原样。图片源和位图也有独立全局预算。
- 首次代理生成是按素材、按质量的单次后台转换，最多两个转换并行。后续源码更新复用代理。初次下载仍受延迟、文件大小和可用带宽约束；带宽低于媒体码率时共同缓冲保留声画同步，不能保证零等待。

代理只服务交互预览，不改变作品源文件、正式编码的音质、分辨率或项目内容。实时会话有租期、空闲释放和容量上限，长时间离开后重新打开即可恢复。受管理的编译和媒体缓存有容量预算，无法纳入预算的资源会明确报错。原生 Remotion 上下文退休时暂停并释放场景引用，其资源回收仍取决于浏览器 GC。

## 版本、引用与导出

实时源码哈希与 Git commit 是不同标识。播放器确认成功应用后才报告实际显示的哈希，Studio 才据此创建审片引用。服务保留近期成功源码和冻结媒体，可在后续语法错误时引用仍然显示的旧画面。引用快照与实时会话分开保存，默认保留期限为 7 天；4 GiB 预算也可能提前回收未被活动或保留任务引用的旧快照；引用任务准备时验证指纹，旧时间点进入只读对照目录，不默认为当前项目位置。

已经保存的旧引用与当前画面不同时，创作页明确提示无法在当前版本准确回放；提交 AI 修改时会携带其冻结源码供比较。快照已到期或素材被篡改时明确拒绝并要求重新选择。

浏览器离线导出开始时锁定实际已显示项目，延迟应用之后收到的版本。场景素材通过该版本绑定的 URL 读取，声音使用原素材；编码期间快速保存不能混入半个新版本。结束或取消后恢复应用最新更新。命令行与平台正式导出仍使用不可变任务源码，既有分段恢复、哈希检查和验证协议保持一致。

## 升级

不需要重写旧作品或破坏已有媒体。平台升级后创作入口切为实时预览，旧 build/导出工具和历史预览兼容。AI 完成修改时做范围、结构、项目测试和类型验证；只有用户要求不可变预览或正式导出时才生成对应任务。

实时预览依赖服务器工具链中的 Vite、FFmpeg 与运行时源文件。浏览器需支持现有 Frame 媒体解码和 Web Audio 能力。保存未被接入工程入口的文件不会自动成为可播放内容；远端素材和自定义网络读取仍需自行满足授权、CORS 与稳定版本要求。


实时预览在无同源权限的沙箱中运行。项目的 `new Worker(new URL('./worker.ts', import.meta.url))` 会打包为 classic Worker，并通过 Blob 引导读取该版本冻结的素材；名称等 classic 选项保持有效，项目仍需在 dispose 时 terminate。当前 Chromium 的此沙箱不能运行 module Worker，即使只执行一行 postMessage 也会失败；显式 `type:'module'` 会给出可操作的错误，改用上述 classic 写法。失败更新保留最后成功的画面。
