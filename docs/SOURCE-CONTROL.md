# 视频预览：源代码管理

视频预览中的同步与版本管理共用一个持久工作面板，不再分成同步侧栏与版本弹窗。面板不阻断桌面播放器；窄屏沿用工作面板的全屏模式。仓库素材库的同步仍保留在仓库设置中，与作品分支操作隔离。

## 入口与基本流程

点击左侧工具栏的“版本”图标（可访问名称为“源代码管理”），或在作品菜单中选择“源代码管理”。`Ctrl / Cmd + Shift + G` 打开面板。上方显示当前作品分支、远端关联状态、待推送／待拉取提交数量及远端检查时间。

推荐工作流：查看变更 → 点击文件审阅差异 → 用 `+` 暂存本次提交的文件 → 填写提交说明 → 提交已暂存 → 同步更改。`Ctrl / Cmd + Enter` 提交已暂存内容。未填写说明、没有暂存内容、作品任务占用或存在冲突时，不允许提交。

**提交不是推送，推送不会自动提交。** 没有关联 GitHub 时仍可进行本地提交、差异审阅与版本恢复。提交说明保存在当前浏览器标签页的 sessionStorage 中，收起面板、切换工具和请求失败不会清空；成功提交才清空。

## 变更与文件差异

“已暂存更改”表示下一次提交将包含的内容；“更改”表示尚未暂存的内容。同一个文件可以同时出现在两个分组：例如暂存后又修改了文件，提交只包含已暂存的部分。

启动 AI、生成预览等操作会自动保存当前文件。若同一文件的暂存版本与工作区版本不同，自动保存会暂停并提示先提交或取消暂存，保留两份内容；未完成的 V5 撤销会使源代码管理面板只读。

每个分组可以折叠，支持文件名与路径筛选。文件显示新增、修改、删除、重命名、类型变化或冲突状态。批量按钮只处理当前筛选列表中的文件，不夹带隐藏文件；列表超限时禁用批量操作。

点击文件打开只读差异：

| 位置             | 左侧基线                               | 右侧内容     |
| ---------------- | -------------------------------------- | ------------ |
| 更改             | 暂存区；未跟踪文件使用空基线           | 当前磁盘文件 |
| 已暂存更改       | HEAD 提交                              | 暂存区       |
| 历史提交中的文件 | 所选提交的第一父提交；根提交使用空基线 | 所选提交     |

差异视图支持行内／并排、原始与新行号、增删计数、自动换行、上一处／下一处差异、复制统一补丁和大窗口审阅。视图偏好保存在本机；文件内容仅作为文本渲染，不解释 HTML。重命名和权限变化即使没有文本差异也保留状态说明。

二进制、Git LFS、非 UTF-8 与超大文件显示类型、大小和可用的对象信息，不伪造文本差异。Git 属性明确标为二进制的文件同样不进入行差异视图。LFS 指针显示真实素材大小与对象 ID，不下载大素材来显示文本。

取消暂存只修改暂存区，不覆盖磁盘内容。撤销未暂存更改必须逐文件确认：已跟踪文件恢复到暂存区内容；未跟踪文件确认后永久删除，无法从 Git 历史恢复。确认窗口打开后文件再次变化，服务端会拒绝旧确认并要求重新检查。

## 历史、视频预览与恢复

“历史”按每页 50 条显示提交说明、时间、短哈希与 HEAD 标记。选择提交可以查看完整哈希、作者及相对于第一父提交的文件变化。此比较不混入当前未提交修改。

每条 Git 版本仍保留“视频预览与比较”入口，继续使用既有隔离历史预览。查看文件差异、选择历史或生成历史视频预览均不恢复当前作品。早期本地快照仍可恢复，但不伪装成有 Git 文件差异的提交。

“命名版本”为干净的已提交状态追加一条命名提交记录，不是 Git tag，不自动暂存或推送。

恢复必须二次确认。暂存区非空时先提交或取消暂存；这是为了避免仅存在于暂存区的中间状态被自动保存工作区时覆盖。未暂存磁盘内容会在恢复前自动保存，之后恢复目标作品目录并追加恢复提交，不重置或删除既有提交，不强推远端。目标历史若含链接或非法路径会被拒绝。当前 `project.ts` 被删除时仍可读取历史并恢复到有效历史版本。

恢复成功后重新核对作品与预览状态，视频预览可通过播放器的“更新预览”重新生成，不在每次暂存或提交时自动构建视频。

## 同步策略

“同步更改”先检查远端，再按需要快进拉取和推送。远端没有当前作品分支时显示“发布分支”。更多菜单提供“检查远端更新”“仅拉取（快进）”“仅推送已提交版本”。

- 远端检查包含清理已消失的远端跟踪引用，不删除本地分支或提交。
- 拉取前本地变更必须处理完；仅允许快进，并且不得覆盖被 Git 忽略的磁盘文件。
- 推送只上传现有提交与关联 LFS 对象。即便工作区仍有修改，也不自动暂存或生成提交。
- 分叉、未完成合并／变基和冲突会停止自动写入。冲突文件可只读查看 base／ours／theirs，需在本地 Git 解决后刷新。工作台不自动选择任何一侧。
- LFS 获取先于快进应用；应用后即便后续 LFS 处理失败，仍核对已变化的源文件，避免界面把已应用操作当作从未发生。

## 隔离、并发与展示边界

只允许操作当前作品的 `projects/<project>/`，以及该分支的 `README.md`、`.gitattributes`、`.gitignore`。其他作品或平台文件不加入变更列表，范围外变更会显示数量警告，含范围外暂存文件的提交被拒绝。敏感路径、缓存、导出目录、符号链接、硬链接及特殊文件不允许在线操作。

受控写操作沿用作品级数据库锁与任务占用检查。锁获取遇到短暂占用会有界等待；一旦进入操作回调就不自动重放，避免重复提交。状态令牌包含 HEAD、分支、索引对象、Git 状态与文件 inode／纳秒时间／大小信息；写入前重新核对，冲突返回 409。它防止正常并行操作使用过期状态，不把可任意篡改宿主机文件的外部进程当作可靠隔离边界。

文件状态通过已有 WebSocket 事件刷新；面板可见时另有 15 秒检查与窗口聚焦刷新。普通暂存、提交或刷新列表不调用 `works_open` 重新扫描全部媒体，避免与紧随其后的写操作争抢锁。

在线展示上限：每侧文本 192 KiB、原始文本补丁 512 KiB、渲染 4,000 行、展示 500 个文件；状态超过 2,000 个变更则明确拒绝在线处理。截断与不支持的内容均有说明，不把部分结果标为完整。此版本按文件暂存，不提供选行／选块暂存、分支切换、交互式变基或在线冲突编辑器。

## 接口与兼容

新功能通过既有鉴权操作注册与 WebSocket 通道提供，无新增数据库表或迁移，无新增依赖。旧 `works_sync` / `works_checkpoint` 接口保留，便于已有 AI／CLI 工作流兼容；新面板不会调用旧的隐式提交并推送流程。

| 操作               | 用途                                                      |
| ------------------ | --------------------------------------------------------- |
| `works_scm_status` | 当前作品的工作区／暂存区文件、状态令牌、占用与远端状态    |
| `works_scm_diff`   | `working` / `staged` / `commit` 文件差异                  |
| `works_scm_commit` | 历史提交详情及文件列表                                    |
| `works_scm_change` | `stage` / `unstage` / `discard` / `commit` / `checkpoint` |
| `works_scm_sync`   | `fetch` / `pull` / `push` / `sync`                        |

`works_scm_change` 必须提供 `expectedRevision`；`discard` 还必须提供单文件路径与 `confirm: true`。同步除 `fetch` 外必须提供 `expectedRevision`。原 `works_restore` 新增可选 `expectedRevision`，新界面始终提供；携带该参数时执行暂存区、范围和冲突检查。
