前三个 MP4 使用逐帧 PNG + FFmpeg 完整生成，FFprobe 核对尺寸、帧率、帧数、时长、音频流，并使用 FFmpeg 完整解码检查，未发现解码错误。WebM 使用浏览器 MediaRecorder 实时录制，确认包含视频和声音，并实际解码；此容器不一定写入全局 duration 元数据，因此不要把它等同于严格固定帧率的逐帧 MP4。

每个 MP4 的 .render.json 记录渲染参数和 FFprobe 结果。汇总：.logs/export-verification.json。实际从输出 MP4 再解码的画面：.logs/export-tiny-seed-25.png。

## 已知边界

这是代码驱动的本机浏览器工作台；没有公网域名部署，没有自动启动服务或云渲染账号。开发服务器只监听 127.0.0.1；重新打开使用根目录的 启动工作台.cmd。

没有 AE/Blender 式拖放关键帧编辑、内置 TTS、素材生成服务、保音高倍速或完整音频 DAW。骨骼、压缩模型加载和后处理提供工具函数，但三个内置示例不覆盖全部外部资产格式组合；导入真实第三方模型后仍需专门测试。

CLI 支持最高 4K/60 FPS 参数；本轮完整成片实测为 1080p/30 FPS，不把参数支持宣传成已完成全场景 4K 性能验证。前台 3D 预览曾显示 60 FPS，仅为当前机器与当前镜头的观察，不是所有设备的性能保证。

三段片子是动画引擎样例与风格演示。工具链已打通不代表后续任何影片天然符合最终交付美术标准。未来仍需要分镜、美术、动作与声音设计，并先验收短样片。
