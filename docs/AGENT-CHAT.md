# 旧版 FRAME Agent 对话记录

当前创作聊天已改用完整官方 Paseo，见 [Paseo 创作工作区](PASEO.md)。下文记录旧版实现契约，供理解保留的历史事件和恢复诊断使用；旧聊天写入入口已删除，不能据此调用新发送操作。

# Agent 创作对话

AI 创作采用连续执行时间线。用户要求、助手说明、公开思考摘要、计划、工具、命令、文件变化和追问按真实顺序显示；不是先把所有文字集中起来，再把工具日志放到最后。播放器、时间轴、提供商分组模型选择、素材引用、版本审片和源代码管理保持现有工作流。

## 阅读与控制

正在执行的步骤直接可见，连续完成步骤可以折叠。已经手动展开的过程不会在后台更新时突然收起。失败步骤和待回答问题不会藏在普通完成状态里。长过程默认只铺开最近 60 个步骤，可以继续展开；搜索会查找当前已加载内容，并打开匹配的工具详情。

助手回复支持 Markdown、列表、表格和带语言高亮的代码块。代码、工具输入、输出、命令和回复可单独复制。原始 HTML 不执行，危险 URL 不成为可点击链接，外部图片不会作为追踪资源自动加载。时间码继续支持审片定位。

命令显示真实命令行、工作目录、已返回的输出、退出码及用时。缺少结束事件的步骤显示“执行已结束，未返回该步骤的结束状态”，不虚构成功。计划条目只使用模型实际返回的状态，不编造百分比。

用户阅读旧内容时不会被新事件拖到末尾；通过“回到最新回复”重新跟随。`Ctrl/⌘+F` 搜索对话中的文字、文件、命令和已加载的工具结果。更早对话仍按需分页。

## 在对话内回答 AI

AI 可以提出单选、多选或自由回答的问题。问题在当前消息流中显示，每次最多四题、每题最多十二个选项。只有全部回答有效后才提交。回答继续**原任务与原上游会话**，不会另建一次创作来冒充继续执行。

答案草稿在当前浏览器标签内保留，刷新不会丢失。问题与已提交答案持久化在服务端，另一个页面回答后会同步显示结果。重复发送同一回答请求返回原回执；同一问题被其他请求回答后不能覆盖。停止本轮会结束待回答问题，不替用户选择默认答案。

等待回答不计入正常执行耗时，但有 24 小时等待上限。关闭 AI 面板不停止任务；关闭浏览器后，任务仍可等待，下次打开会读取待回答记录。新写的创作要求仍按作品队列执行，不会被错误地当作当前问题的答案。

问题只用于必要的创作澄清，不是新增的执行审批层。平台保留现有直接执行权限及作品隔离边界。密码、API 密钥等凭据应在设置里配置，不通过问题卡收集。

## 文件审查与结果

文件工具返回的差异属于对应步骤；命令直接写文件也会通过隔离工作区的 Git 差异检查进入本轮清单。清单区分新增、修改、删除、链接及二进制，显示已记录的增删行。点击文件可查看只读逐行差异、切换文件、换行和复制差异。

运行中的工作副本不等于正式作品。只有原有校验和发布流程成功，才显示“已完成并保存”。“查看本轮预览与修改”继续使用 V5 的确切前后版本、引用版本及安全撤销，不打开一个与该轮无关的最新结果。步骤差异也明确标注不是本轮最终净变更。

工具输出和大文件差异有边界及截断提示；不会为显示日志去截断作品源码。差异检查不暂存文件，不运行 textconv 或外部 diff，不跟随链接读取任意目标，也不读取其他作品。

## 通知

作品工具条和全局导航提供 Agent 通知入口。待回答、完成、失败会形成持久通知；普通工具执行不逐条打扰。点击通知定位具体作品、对话和轮次。历史问题区分“已回答”“提问已结束”，不永远显示等待。

网页内重要提醒默认启用；桌面通知仅由用户在通知设置中主动授权，并只在窗口失焦时触发。通知默认无声音。浏览器拒绝权限时显示恢复说明，网页通知仍可用。

这里不是离线 Web Push：关闭浏览器期间的事件保留在通知中心，重新打开后读取，不承诺系统在浏览器已关闭时弹出通知。

## 执行器与协议

- Codex 使用 `app-server` 的双向 JSON-RPC，包括 thread/turn/item、动态 `frame_ask_user` 和原生 `requestUserInput`。
- Claude 使用 `stream-json` 双向输入及 `can_use_tool` 控制响应，将 `AskUserQuestion` 的真实答案回传给同一任务。
- 两者还可以调用 `node scripts/work-tool.mjs ask '<JSON>'` 使用同一持久问答通道。该工具只能创建/读取本任务的问题，不能替人填写答案。

公开事件统一为版本化 `agent-item`。一次 CLI 消息可产生多个内容块，每个块保留自己的身份和首发位置。Codex 原始 `reasoning/textDelta`、加密内容、签名等不显示；没有公开摘要时明确提示未提供，不用固定一句“思考中”伪装真实内容。

问题创建、回答和事件文件游标使用同一数据库事务锁，避免问题超越已经输出的消息。事件读取同时按行数和字节分页，并返回 `hasMore`；客户端和 WebSocket 消费这个标志，不能把不足 100 行误认为历史结束。

新增数据库迁移 `0009-agent-interactions` 增加问题、通知与等待计时，不删除旧对话。旧版消息/活动记录仍可读。更新时 API、controller 和 executor 必须使用相同的平台版本；需要完成正常候选发布验收，不以开发测试代替上线操作。

## 兼容边界

已安装的 Codex `0.158.0` 和 Claude Code `2.1.283` 完成原生协议验证。工具版本变化应继续执行原生测试，不能把不支持交互的旧版本静默降级为一次性 stdin 后仍声称可以等待回答。

本功能对齐编辑器 Agent 的核心操作链路，不意味着实现了完整 VS Code/Codex IDE 的所有功能。运行中输入目前明确排队，不伪装即时 steering；非本次支持的交互请求会返回可见错误。发布、文件应用、回滚和生产权限仍由平台原有执行边界处理。
