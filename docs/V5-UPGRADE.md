# V5 内容协议与迁移兼容

本文保留 V5 引入的内容协议和数据库兼容边界。当前 AI 创作使用共享 [T3 Code](T3-CODE.md)，作品工作区、审片引用和后台导出的现行契约见 [AI 工作台](AI-WORKBENCH.md)。

## 作品内容与预览

V5 保留场景、音频和绝对时间协议 1。已有作品目录、源码接口、多音轨、Git 分支与素材继续使用，不要求为升级重写内容。`project.ts` 可用 `beats` 中唯一的可选 `id` 标识镜头；未声明镜头 ID 的作品仍按版本和时间定位。

编译预览与作品源码分别版本化。播放器格式或公共运行时改变后，按当前运行时身份重新构建旧预览；不把预览缓存迁移写入作品源码。实际预览版本以 `server/preview-version.mjs` 为准，历史 V5 的格式号不代表当前播放器版本。

作品版本保存在 Git 历史中，`works_restore` 恢复整个历史作品并追加提交。审片引用可以带实际显示的源码 revision、预览任务或源提交，以及时间、选段和素材；历史画面不代表当前源码。当前原生回合的历史与检查点由 T3 管理，FRAME 作品检查绑定确切 revision，源码继续变化后旧报告显示过期。版本操作见 [源代码管理](SOURCE-CONTROL.md)。

## 数据库迁移与降级

V5 通过 `0007-creation-workflow.sql` 与 `0008-scoped-realtime.sql` 增加创作元数据和定向通知。它们是已发布的历史迁移，仍由串行迁移器按 SHA-256 校验；不能修改已应用脚本来替代新迁移。后续迁移已退役旧 AI 任务、连接和撤销路径，当前接口以 T3 与 AI 工作台指南为准。

**旧程序会拒绝不认识的新数据库版本，迁移后不能仅切回任意旧镜像就当作回滚。** 升级须在隔离数据上验证候选与迁移过程。FRAME 应用、controller 和执行器保持匹配；T3 使用独立版本，并按当前接入契约验证。问题优先通过兼容现有 schema 的修正版处理，确需降级时另行审查数据库与文件的一致性，不自动删除迁移记录。

作品内容协议与软件部署版本独立。V5 没有改变语音服务协议；当前语音镜像与配置仍以部署模板和语音指南为准，不能沿用历史文档中的固定镜像号作为升级要求。

## 当前升级与验收入口

部署、活动任务检查、必要服务切换和上线验收见 [服务器部署](SERVER.md)，T3 独立升级见 [T3 Code](T3-CODE.md)。发布默认不做数据库转储或作品/模型全量归档；已有旧镜像和用户已有备份保留，不可逆数据操作另行确认。

统一检查入口为 `pnpm verify`、隔离候选环境中的 `pnpm verify:release` 和工作区布局回归 `pnpm test:workspace`，具体门禁见 [验证说明](VERIFICATION.md)。测试夹具不替代外部账号真实授权、付费模型能力或作品级艺术质量审片。V5 当时的实施与验证属于[历史记录](../records/v5-upgrade-20260929.md)，不作为当前功能指南。
