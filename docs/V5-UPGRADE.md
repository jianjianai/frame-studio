# FRAME 5：版本明确的直接创作

V5 保留 AI 直接执行。没有讨论模式、只读聊天模式或额外逐次审批；AI 继续在独立作品任务中使用已有工具，校验通过后自动保存版本并发布预览。作品范围、凭据和宿主机隔离仍然有效。

## 每轮创作

在作品页选择提供商和模型，引用当前时间、选段或素材，提交要求。请求在服务器持久化后入队；关闭面板或浏览器不停止服务器任务。排队说明区分作品前序任务、同一模型连接占用、可用槽位、控制器心跳和待恢复的结果。

提供商、模型、认证方式和端点在入队时固定。密钥不写入任务记录；执行时从原连接读取凭据。模型被停用、端点改变、密钥轮换或官方身份重新登录后，旧排队任务不会悄悄改用另一身份或模型，需要重新选择后提交。更改连接显示名不影响已有会话。

只有执行配置身份匹配时才续接原上游会话。切换工具、模型或账号会建立新执行会话，并传入有界的近期持久对话，而不是把不同账号的 session ID 混用。当前上限为 12 轮、每轮请求和回复各最多 4000 字符，总计 24000 字符；这是执行器上下文承接，不是对完整聊天记录的删除或压缩。

请求键用于识别重试，原始提交与经服务端补充的执行输入分别保存。网络中断仅表示回执不确定，前端不自动重放写操作；先检查任务状态，再重试原提交。

## 审片引用

引用同时保存作品、预览任务或源码提交、时间/选段，以及可选镜头 ID。预览和提交由服务端验证归属，不能引用另一作品的任务。作品可在 `project.ts` 的 `beats` 中声明唯一的可选 `id`；没有镜头 ID 的旧作品继续按版本和时间定位。

如果执行时作品已经有后续修改，旧时间码仍属于被引用的版本。执行器提供该版源码的独立参考副本，AI 应比较参考与最新作品后在最新作品上修改；不能直接将旧版覆盖回来。无法确定对应镜头时应明确说明，不声称时间码已经自动精准映射。参考目录不属于允许修改的作品目录。

点击旧消息的版本引用会打开相应历史预览，不恢复源码、不切换作品分支。历史版本可能需要重新构建；这是明确标识的服务器任务。旧记录缺少版本信息时显示其兼容状态，不伪造来源版本。

## 本轮修改与审片

每轮成功结果提供“查看本轮预览与修改”。该界面展示确切的修改前后 Git 提交、文件差异、当前作品版本和实际执行器记录的检查结果。可切换修改前、修改后，以及必要时更早的原引用版本；同一时间只挂载一个历史播放器，避免两份音频同时播放。

选段是用户提出要求的位置，不等于程序已证明的全部画面影响范围。界面明确区分文件差异、AI 对影响的描述和实际工具检查。没有逐项检查记录的旧任务不会显示虚构的通过标记。

“基于正在看的版本继续调整”把该版本和当前审片位置带回草稿，不会未经用户发送直接开始新任务。

## 安全撤销一轮修改

撤销使用本轮前后提交生成逆向差异，在临时 Git 索引中应用到当前版本。保留后续无关修改；不能合并的冲突会停止，不覆盖正式作品。成功后追加新提交，不重置分支历史。当前分支、源码指纹和未保存文件会再次检查，打开审片后发生的新变更会使过期撤销请求失败。

撤销具有持久请求标识及恢复记录。文件替换、Git 引用和数据库保存之间发生中断时，使用“重试完成撤销”恢复同一结果，不重新执行 AI。待恢复的撤销会阻止同作品的其他写入和任务领取，但不阻塞其他作品。成功后恢复临时目录被清理，失败记录保留用于恢复。这里的操作恢复副本不是发布前全量备份。

已有明确前后版本的旧任务可以审查；没有可证明修改基线的旧记录不能自动撤销。撤销与“恢复整个历史版本”是不同操作，后者仍在版本管理中提供。

## 状态与性能

管理页面、播放器和本机导出分别拥有自己的生命周期；关闭 AI、素材或导出面板不等于销毁作品会话。本机导出仍需要保留标签页，离页会提示；服务器导出不依赖浏览器持续打开。预览连接暂时失败时可以重试加载现有构建，不必重新运行 AI 或重新构建。播放器 15 秒内未确认本机导出的启动或停止请求时，工作台重建该播放器实例以终止不确定的本机编码，明确显示错误；不会对正常运行的长时间导出套用这个超时。迟到的进度消息不能把“停止中”改回“运行中”，也不能覆盖已完成的结果。

主要页面按路由加载代码。任务事件通过 PostgreSQL 持久保存，NOTIFY 仅携带作品/任务标识来定向刷新相关订阅。旧表名通知和重连仍执行保守的全量状态恢复；通知不是事件存储。

诊断记录实际排队、准备、AI、检查、编译、音频准备和结果保存的耗时。音频指标显示实际复用、生成和编码片段数，现有分轨缓存及失效检查保留。不按主观估计显示 AI 完成百分比，也不承诺任意作品可以安全地只重建几秒。

## 接口

网页、HTTP、WebSocket 与 MCP 复用业务操作注册器。主要作品、预览、任务、版本和连接操作共享请求/响应校验；播放器控制消息使用同一校验定义。并非所有既有 JS/JSX 都已迁移为 TypeScript，类型检查范围以 `tsconfig.platform.json` 为准。

新增操作：

- `works_result({id, task})`：读取本轮确切版本、文件变化、工具证据及当前撤销条件。
- `works_undo({id, task, requestKey, expectedCommit, expectedRevision})`：在乐观版本条件下逆向撤销；重试必须使用原标识和原条件。
- `works_queue_status({id})`：读取当前排队原因及控制器就绪状态。

审片上下文可附带 `previewTask`、`sourceCommit`、`shotId`。原来的 `time/start/end/assets` 保持兼容。结构化操作错误提供 `error/status/code/recovery/retryable/requestId`，例如 `UNDO_BASE_CHANGED`、`UNDO_RECOVERY_REQUIRED`、`EXECUTION_SELECTION_CHANGED`。连接中断或响应超时的客户端错误使用 `OPERATION_UNCERTAIN`，不会自动重试写操作。

## 升级与兼容边界

产品版本为 5.0.0，场景/音频协议仍为 1，编译预览格式提升为 10。旧作品目录、源码接口、多音轨、Git 分支与素材保持原样。旧预览按运行时身份正常重建，不把缓存迁移写入作品源码。语音服务没有破坏性改动，部署示例继续使用已存在的 `frame-speech:4.2.0`。

数据库新增迁移 `0007-creation-workflow.sql` 和 `0008-scoped-realtime.sql`，添加字段、撤销记录及通知触发器，不删除旧作品或历史。迁移由已有的串行迁移器管理，不在 Dockge 中增加退出即留在栈内的一次性服务。

**旧二进制的迁移器会拒绝不认识的新数据库版本。迁移之后不能承诺直接切回任意旧镜像就能回滚。** 发布前应在隔离测试数据上验证候选版本和升级过程，应用、控制器、执行镜像需保持匹配，检查活跃任务后再进行授权更新。问题优先通过兼容新 schema 的修正版处理；确需降级时另行审查数据库与文件的一致性，不自动删除新增迁移记录。

发布默认不做数据库转储或作品/模型全量归档。已有旧镜像和用户已有备份不自动删除；用户另行要求备份或不可逆数据操作时再明确处理。本分支代码升级本身不等于镜像已发布或生产环境已更新。

## 验收

统一入口仍是 `pnpm verify` 和隔离候选执行器环境中的 `pnpm verify:release`，工作区布局另外执行 `pnpm test:workspace`。V5 测试覆盖配置固定、版本归属、幂等重试、逆向冲突、两次目录重命名之间的恢复、真实定向通知、前后实际画面和安全撤销。测试中的模型服务是明确的固定响应夹具，不冒充对外部付费模型的人工验收。

实际执行记录和尚未验证项见 `records/v5-upgrade-20260929.md`。长片声音、运动与艺术质量仍需作品级真实审片，不能由平台测试代替。
