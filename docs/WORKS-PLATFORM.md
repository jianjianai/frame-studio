# FRAME 作品管理与 AI 创作平台

产品中心是 AI 创作的作品。作品库或仓库作品列表进入创作页；播放器、时间轴和 AI 对话是常驻区域。关闭浏览器不会主动停止 T3 原生回合或 FRAME 后台导出。完整交互与技术契约见 [AI-WORKBENCH](AI-WORKBENCH.md)。

平台代码仓库为 `jianjianai/frame-studio`；现有作品已迁入独立的私有作品仓库 `jianjianai/frame-works`。作品仓库不是平台仓库的子模块，也不包含平台代码。平台仓库的 `/projects/` 仅供临时测试工作区使用，被 Git 和 Docker 忽略。日常创作使用作品唯一工作目录，公共引擎与依赖由共享 FRAME 运行时提供；后台导出才冻结单个作品到本次任务的隔离目录。

## 内容与运行时

每个作品有稳定 UUID，在内容仓库中独占 `works/<slug>` 分支和 `projects/<slug>/` 目录。独立根提交隔离其他作品历史；本地 Git worktree 隔离工作区。新建作品选择仓库后只输入名称。共享引擎、依赖和制作工具由平台镜像提供，仓库只存内容。

作品资料保存在 `production/work.json` 并索引到数据库。回收站保留源码与素材；删除需完整名称确认。版本保存到作品分支 Git，恢复追加提交，旧平台的本地快照仍可恢复。素材库使用仓库的 `frame/materials` 分支，使用时复制进入作品 `public/` 并记录来源。未引用按作品资源文件实际内容统计，包括回收站作品。

预览只运行当前作品的播放器组件（画面、播放控制、时间轴），不加载工作台的首页、导航或素材管理页面。实时播放器观察作品权威目录，在隔离的预览文档中运行；后台构建和导出使用各自的执行器。

## 统一操作

网页、MCP 与 CLI 使用同一组 `works_*` 操作：列出、创建、打开、编辑资料和源码、复制、回收恢复、素材、配音、预览、导出、版本与创作上下文。AI 对话使用 T3 原生接口。外部 AI 以作品 UUID 操作，无需拼接仓库和工程路径。工具发现、精简上下文、文件分页与补丁、任务游标、CLI 等待/下载和断点上传见 [PLATFORM-TOOLS](PLATFORM-TOOLS.md)。

共享 T3 中的 AI 在当前作品的权威 cwd 使用 `film` 工具编辑与审片；`work-tool.mjs` 提供作品范围内的素材搜索、素材导入和语音合成。FRAME 工具凭据绑定作品及原生 thread，调用时核对 project、cwd 和线程活动状态；不把管理员凭据传给 AI。原生项目、对话与配置边界见 [T3 Code](T3-CODE.md)。

具备浏览器能力的 AI 调用 `works_browser` 获得专用审片页，以 `FRAME_AI` 控制台 API 查看帧、播放片段、截图和导出。服务器只进行源码编译，渲染、音频与编码在 AI 的浏览器执行。接口与限制见 [AI-BROWSER](AI-BROWSER.md)。

## 页面

- 作品库、最近打开、仓库列表与仓库作品列表。
- 作品创作页：画面、多轨时间轴、当前作品的原生 AI 对话与创作面板；完整 T3 页面提供文件、Git 和终端。
- 素材库：按仓库上传、预览、来源与标签、作品引用、未引用筛选、回收站与同步。
- 后台项目：按作品聚合原生对话、终端、权限状态和 FRAME 后台任务，可打开作品或按作品停止。
- 设置：AI 助手链接到 T3 原生设置及 CLI 配置；保留独立工具升级、GitHub 多账号、语音引擎/模型及测试、MCP 令牌。密码仅环境变量配置。

验收以“新建作品 → 对话/编辑 → 预览 → 配音与素材 → 导出 → 同步”为主线，另验证刷新重开、原生状态重连、后台任务连续性和移动端。
