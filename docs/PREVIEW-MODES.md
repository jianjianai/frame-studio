# 预览素材模式与浏览器完整缓存

工作台从左侧功能区的「素材模式」进入右侧面板，独立预览仍保留素材模式工具栏。面板提供三个模式。模式与画面质量分开；更改预览模式不会修改作品素材、混音文档或正式导出。

| 模式     | 服务器工作                                                     | 浏览器工作                                               | 适用场景                               |
| -------- | -------------------------------------------------------------- | -------------------------------------------------------- | -------------------------------------- |
| 原始素材 | 编译项目代码、发布安全资源快照，直接传输原素材；不生成媒体代理 | 解码原图、视频、音频、音色库并实时合成                   | 检查源素材品质、开发音频和特效         |
| 压缩素材 | 按需生成与复用图片、视频、音频代理；多个预览共享相同代理任务   | 解码代理并实时合成                                       | 网络较慢或原素材很大                   |
| 完整缓存 | 提供原始素材和运行代码的完整版本清单；不生成媒体代理           | 下载、校验、持久保存并准备播放，完成后通过本地 Blob 读取 | 反复播放、定位、音乐编排，减少网络等待 |

“服务器不处理”指不转码、缩图或压缩媒体。项目代码编译、安全路径检查、权限验证、哈希和版本快照仍由工作台提供。正常预览不提前导出整部视频或整首音乐。

## 使用

从作品页面左侧功能区打开「素材模式」，在右侧面板选择模式；窄屏通过「工具」菜单进入。独立预览仍使用素材模式工具栏。工作台记住选择；改变模式会准备对应资源并更新同一个播放器，保留播放位置和控制状态。正式导出期间冻结预览版本，完成后恢复更新。

完整缓存显示：

- 已完成字节 / 总字节、文件数和进度条；
- 尚未完成的文件，包含下载状态、大小与失败原因；
- 下载后准备画面、音频和运行依赖的状态；
- 持久缓存空间不足或不可用的提示；
- 取消、重试及清理本作品缓存操作。

取消仅停止本预览的下载请求；多个预览共同使用的服务器任务仍由其他使用者继续。错误保留可重试入口，旧已接受版本仍可使用。正在播放时的新版本先缓存与初始化，再同时接受画面、声音和样式。原素材、采样或音色库发生变化时，音频生成器也重新准备，避免继续使用旧音色。

## 缓存内容与一致性

服务器清单包括项目 public 下的原始资源、编译后的模块与 Worker、工作台运行依赖、字体及其 SHA-256、字节数和 MIME。覆盖项目动态读取的素材，不只追踪静态 import。运行时引用项目之外的资源不属于此完整缓存契约；制作时将所需资源放到项目 public 并通过 assetUrl 访问。

浏览器按内容哈希复用文件。下载流增量校验，不把整份大音色库复制进一个 JavaScript 数组；小文件有限并发，大文件限制同时传输数。新版本立即开始缓存，仅下载缺失内容。已缓存的原始音视频支持 Range 请求，Worker、AudioWorklet、WASM 和字体也从对应缓存映射读取。

工作台的可信父页面持有 CacheStorage。播放器继续使用原有 opaque iframe 隔离，父页面只接受该 iframe 的消息，并按服务器清单验证路径、哈希、版本和大小。独立打开的安全预览只保留本页面缓存，会明确提示；从工作台打开可复用持久缓存。

“完整缓存就绪”表示当前版本资源下载、完整性校验、场景和当前音频窗口准备已完成。之后的播放使用已缓存资源，浏览器仍需计算解码、DSP、合成和绘制。浏览器可能自行回收非持久存储；下次打开会校验并补下载。缓存不会把整部作品提前合成为 PCM 或视频，也不保证设备在超出算力时仍维持帧率。实时麦克风输入需要当前授权和设备，不能缓存未来声音；可先录成项目素材再使用完整缓存。

## AI 使用

预览控制在首次完整下载之前就可调用，便于 AI 观察和恢复：

```js
FRAME_AI.preview(); // mode、cache、已接受 revision
FRAME_AI.setPreviewMode("cached"); // original | compressed | cached
await FRAME_AI.waitPreviewCache({ timeoutMs: 300000 });
FRAME_AI.retryPreviewCache();
FRAME_AI.cancelPreviewCache();
await FRAME_AI.clearPreviewCache();
```

waitPreviewCache 只接受当前模式、当前清单的 ready，不能把旧版本完成误当成新版本完成。取消、失败、离开模式或超时返回可识别错误。缓存完成后继续使用 FRAME_AI 的 frame/seek/play 与诊断接口。

服务端 works_live_preview / frame_works_live_preview，以及 works_browser / frame_works_browser 的 live 模式均可传 mediaMode。浏览器 URL 的 mediaMode 是每个观看者的偏好，同一源码会话可以被不同模式的观看者共享，不相互覆盖。CLI/MCP 的具体参数通过工具 schema 或 film help 查询。

## 压缩与导出

显式压缩模式在高画面质量下仍使用代理。导出冻结期间的资源解析强制回到原始文件；离线音频上下文也只读取原音。代理任务使用有限 FFmpeg 并发；最后一个使用者取消时终止尚未完成的任务、删除本任务临时输出。已完成的共享代理继续按工作台缓存策略复用。

接口和架构见 [实时预览](V8-LIVE-PREVIEW.md)、[音频创作](AUDIO-CREATIVE.md)。验证过程与发布身份见根 records。
