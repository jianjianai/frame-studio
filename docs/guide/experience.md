# experience：经验库

经验库是同类作品共用的制作经验（例如“知识类视频”“音乐视频”），是一个 Markdown 文档文件夹，用 Git 管理版本。一个作品可以关联多个经验库（`project.ts` 的 `experiences`，由用户在「经验」面板中选择；用户要求时用 `experience_link` 关联、取消关联或新建）。作品库里的经验库可能很多：`experience_list` 按名称、介绍和文档标题查找（`query`，例如“开场”“卡点”），不给 query 时本作品关联的在前，其余按和本作品的相近程度和使用次数排列，并写出相近的地方（名称、介绍或内容相近，类似的作品在用）；关联前先征得用户同意，没关联的也可以先用 `experience_read`（`library` 参数）看看。删除的经验库在回收站里，AI 用不了也恢复不了：提示里说某个经验库“在回收站里”时，请用户在「经验库」选项卡的回收站中恢复。关联了多个时，读写文档用工具的 `library` 参数指定是哪个，新经验写进内容最相关的那个。还没有作品时，`experience_read` / `experience_write` / `experience_commit` 用 `repo` 指定作品库，读写用 `library` 写明经验库。作品关联经验库后：

- 会话说明只写了作品关联了哪些经验库，内容由你按需要用 `experience_read` 读（不给 path 时是 README 和文档目录）；找某个主题的经验用 `search`，`scope: ["experience"]`。外部 AI 用 `work_context` 的 `experiences`。
- 用户或其他对话改了经验库时，下一条消息的 `[FRAME]` 会说明哪些文档变了，需要时重新读。
- 记什么、记在哪里由你判断：只和这一部作品有关的写进作品自己的 `AGENTS.md`；可以复用的写进合适的关联经验库（`experience_write` 的 `edit`、`write`、`delete`、`move`，一次可以改几篇）；没有合适经验库的先写进作品的 `经验.md`，以后整理进经验库。关联或新建经验库要用户同意。
- 经验库的修改（`experience_write` 写的、用户在工作台里改的）不会自动保存为版本：用户在「版本与同步」里按经验库保存、查看和恢复，或用 `experience_commit` 保存（`library` 只存一个，不写则有修改的各存一个，`message` 是版本说明）。作为经验库关联的技能（`skill:<技能名>`）例外：它的修改按技能保存（对话中在每轮结束时，`experience_write` 的 `note` 是版本说明）。
- 用户要“整理经验”时，把 `经验.md` 里的条目合并进合适的经验库，合并后从 `经验.md` 删掉。
- 作品按 id 关联经验库，id 不会变；改名（用户在选项卡里改，或你改 README 的第一个「# 」标题）只改显示的名称。

## 值得记录的

- 用户纠正过你的地方（“标题不要用衬线体”）和明确表达的喜好。
- 反复试了才成功的做法、踩过的坑和原因。
- 这一类作品通用的结构、节奏、配色、字体、配音和配乐选择。
- 复盘得出的结论：哪些做法让留存、完播率或互动明显更好或更差（附数据和作品 id，见 `reviews`）。
- 好用的代码片段（短小、可直接复用）、素材来源。

只和这一部作品有关、换一部作品就不成立的内容，写在作品自己的 `AGENTS.md`，不进经验库。

## 怎么组织

结构由你决定，经验库、`AGENTS.md`、`经验.md` 都由你来保持整洁、精练；一篇文档太长、不好读也不好找时，按主题拆成几篇。平台只依赖两点：

- `README.md` 是经验库的入口，不能删除或改名；它的第一个「# 」标题就是经验库显示的名称，标题后的第一段是介绍。
- 目录（`experience_read` 不给 path 时）列出每篇文档的第一个「# 」标题和第一句话，所以每篇的开头写清楚讲什么，读的人才找得到。
