# experience：经验库

经验库是同类作品共用的制作经验（例如“知识类视频”“音乐视频”），是一个 Markdown 文档文件夹，用 Git 管理版本。一个作品可以关联多个经验库（`project.ts` 的 `experiences`，由用户在「经验」面板中选择；用户要求时用 `experience_link` 关联、取消关联或新建）。作品库里的经验库可能很多：`experience_list` 按名称、介绍和文档标题查找（`query`，例如“开场”“卡点”），不给 query 时本作品关联的在前，其余按适合本作品的程度和使用次数排列，并说明为什么适合（名称相近、同一系列或类似的作品在用）；关联前先征得用户同意，没关联的也可以先用 `experience_read`（`library` 参数）看看。删除的经验库在回收站里，AI 用不了也恢复不了：提示里说某个经验库“在回收站里”时，请用户在「经验库」选项卡的回收站中恢复。关联了多个时，读写文档用工具的 `library` 参数指定是哪个，新经验写进内容最相关的那个。还没有作品时，`experience_read` / `experience_write` / `experience_commit` 用 `repo` 指定作品库，读写用 `library` 写明经验库。作品关联经验库后：

- 内置 AI 的会话说明（作品根目录的 `AGENTS.md`）里已经有它：经验库小时是全部文档，大时是 README 和其他文档的目录。与当前任务相关的文档用 `experience_read` 读全文，照着已有经验做；没有变化的不用重复读。作品没有关联经验库时，会话说明列出几个可能适合它的（或用得最多的），`work_context` 的 `experiences.offers` 也是。
- 外部 AI 用 `work_context` 得到 README 和目录，或用不带 path 的 `experience_read`。
- 找某个主题的经验（例如“转场”“字幕”）用 `search`，`scope: ["experience"]`：返回匹配的文档和行，再读相关的全文。
- 用户或其他对话改了经验库时，下一条消息的 `[FRAME]` 会说明改了什么。
- 制作中发现值得记住的东西就当场记下来，按内容放三个地方：
  - 只和这一部作品有关、换一部作品就不成立的：作品自己的 `AGENTS.md`。
  - 可以复用、且关联的经验库里有适合这类作品的：写进那个经验库（`experience_write` 的 `edit`、`write`、`delete`、`move`，一次可以改几篇）。写之前想一想：换一部同类作品还成立吗？
  - 可以复用、但没有关联经验库或关联的都不适合：作品的 `经验.md`（一条一个「## 标题」，写法同下面）。不要为了记经验自己关联或新建经验库。
- `experience_write` 的 `note` 写一句这次记了什么：对话中每轮结束时，改过的经验库各自自动保存为一个版本，`note` 就是版本说明（没有对话时写入后立即保存）。用户在「版本与同步」里按经验库查看和恢复。用户在工作台里手动改的，用户要求时用 `experience_commit` 保存。
- 用户要“整理经验”时：把 `经验.md` 里的条目合并进合适的经验库，合并后从 `经验.md` 删掉；没有合适的就用 `experience_list` 找，或建议新建，用户同意后再关联或新建。
- 作品按 id 关联经验库，id 不会变；改名（用户在选项卡里改，或你改 README 的第一个「# 」标题）只改显示的名称。

## 值得记录的

- 用户纠正过你的地方（“标题不要用衬线体”）和明确表达的喜好。
- 反复试了才成功的做法、踩过的坑和原因。
- 这一类作品通用的结构、节奏、配色、字体、配音和配乐选择。
- 复盘得出的结论：哪些做法让留存、完播率或互动明显更好或更差（附数据和作品 id，见 `reviews`）。
- 好用的代码片段（短小、可直接复用）、素材来源。

只和这一部作品有关、换一部作品就不成立的内容，写在作品自己的 `AGENTS.md`，不进经验库；单个作品的数据和经过如果能说明某条结论，放进经验库的详细文档。

## 怎么组织

经验库有两种文档：

- **结论文档**：`README.md` 和 `详细/` 以外的文档。只写结论和做法，精简：动手前要对照它们。所有结论文档加起来不超过约 24 KB（中文约 8000 字）；超过时会话说明、`work_check` 和「经验」面板会提示需要整理——先告诉用户，用户同意后把结论合并精简，例子、数据、过程移到详细文档。结论文档小（约 12 KB 以内）时会话说明里是全文，否则只有 README 和目录，读和当前任务相关的。
- **详细文档**：`详细/` 下的文档。支撑结论的细节、例子、数据、过程和单个作品的记录，完整保留，不用精简；会话说明里只有目录，需要时用 `experience_read` 读。

- `README.md` 是入口：一句话说明这个经验库，“用户偏好”和“通用做法”两节放最常用的经验。不用在 README 里维护文档列表，目录由每篇文档的标题和第一句自动生成。
- 按主题分文档，例如 `开场.md`、`配色与字体.md`、`节奏与转场.md`、`配音与配乐.md`、`常见问题.md`；对应的细节放 `详细/开场.md` 这样的同名文档。一篇文档讲一个主题，新经验合并进已有文档，不要每次新建。
- 每篇文档第一行是 `# 标题`，下一行用一句话说明讲什么（这句话就是它在目录里的说明）。
- 结论文档里每条经验写清楚，细节指向详细文档：

```markdown
## 鼓点对齐转场
- 什么时候用：有背景音乐、需要切镜头或转场时
- 做法：用 preview_audio 找响度峰值，把转场放在峰值前 1–2 帧
- 避免：按固定秒数切，听起来和音乐脱节
- 细节：详细/节奏与转场.md（work-0560feb5 的对比，2026-10）
```

- 结论文档写结论和做法，不写过程流水账；有冲突时以最新确认的为准，删掉过时的说法。过程和数据放详细文档，不要删。
