# experience：经验库

经验库是同类作品共用的制作经验（例如“知识类视频”“音乐视频”），是一个 Markdown 文档文件夹，用 Git 管理版本。一个作品可以关联多个经验库（`project.ts` 的 `experiences`，由用户在「经验」面板中勾选）。关联了多个时，读写文档用工具的 `library` 参数指定是哪个，新经验写进内容最相关的那个。作品关联经验库后：

- 内置 AI 的会话说明（作品根目录的 `AGENTS.md`）里已经有它：经验库小时是全部文档，大时是 README 和其他文档的目录。与当前任务相关的文档用 `experience_read` 读全文，照着已有经验做；没有变化的不用重复读。
- 外部 AI 用 `work_context` 得到 README 和目录，或用不带 path 的 `experience_read`。
- 用户或其他对话改了经验库时，下一条消息的 `[FRAME]` 会说明改了什么。
- 制作中发现值得记住的东西就当场整理进去：`experience_edit`（改几处）、`experience_write`（新建或整篇重写）、`experience_delete`（合并后删掉旧文档）。
- 修改是未保存状态，用户在「经验」面板里查看改动、保存版本、同步到 GitHub。

## 值得记录的

- 用户纠正过你的地方（“标题不要用衬线体”）和明确表达的喜好。
- 反复试了才成功的做法、踩过的坑和原因。
- 这一类作品通用的结构、节奏、配色、字体、配音和配乐选择。
- 好用的代码片段（短小、可直接复用）、素材来源。

只和这一部作品有关、换一部作品就不成立的内容，写在作品自己的 `AGENTS.md`，不进经验库。

## 怎么组织

- `README.md` 是入口：一句话说明这个经验库，“用户偏好”和“通用做法”两节放最常用的经验。不用在 README 里维护文档列表，目录由每篇文档的标题和第一句自动生成。
- 按主题分文档，例如 `开场.md`、`配色与字体.md`、`节奏与转场.md`、`配音与配乐.md`、`常见问题.md`。一篇文档讲一个主题，新经验合并进已有文档，不要每次新建。
- 每篇文档第一行是 `# 标题`，下一行用一句话说明讲什么（这句话就是它在目录里的说明）。
- 保持精简：整个经验库不超过约 12 KB（中文约 4000 字）时，AI 每次对话都能看到全部内容；更大时只看到 README 和目录。
- 每条经验写清楚：

```markdown
## 鼓点对齐转场
- 什么时候用：有背景音乐、需要切镜头或转场时
- 做法：用 preview_audio 找响度峰值，把转场放在峰值前 1–2 帧
- 避免：按固定秒数切，听起来和音乐脱节
- 来源：work-0560feb5（2026-10）
```

- 写结论和做法，不写过程流水账；有冲突时以最新确认的为准，删掉过时的说法。
