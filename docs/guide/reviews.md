# reviews：发布后的复盘

作品发到平台以后，记录它的表现、和其他作品比较，把结论变成下一部作品的经验。

复盘资料在作品库的 `frame/reviews` 分支，每个作品一个文件夹（文件夹名是作品 id），不在作品自己的分支里：作品发布后只能查看，数据还可以一直补充。每次修改自动保存为一个版本，连接了 GitHub 时自动同步。

```
<作品 id>/
  review.json      发布记录、各次统计的数据、观众留存曲线（用 review_write 修改，不要手写）
  复盘.md          复盘文档（可以有几篇）
  raw/             平台后台导出的表格、截图等原始文件，原样保存，不能修改
```

用户在工作台左侧「复盘」里上传原始文件、记录发布、录入数据；首页的「复盘对比」把所有作品放在一起比较。

## 工具

- `review_read`：发布记录、最新数据、留存分析（流失明显的地方和对应的镜头、字幕）、文档和原始文件列表。`file` 读一个文件：xlsx / csv 读成文字表格，截图返回图片，文档返回全文。
- `review_write`：`operations` 按顺序执行，一次调用保存一个版本。
- `reviews_compare`：每条发布记录一行，取发布后同一天数的数据，带比例和中位数。
- 外部 AI 手上的表格、截图用 `upload_link` 的 `review: true` 上传到 `raw/`。

## 记录数据

```json
{
  "operations": [
    { "op": "post", "platform": "抖音", "postedAt": "2026-10-08T20:00:00+08:00", "url": "https://…", "export": "夏日海报-2026-10-08-12-00-00.mp4" },
    { "op": "snapshot", "post": "p1", "at": "2026-10-15T20:00:00+08:00", "source": "raw/抖音-近7天.xlsx",
      "metrics": { "views": 12034, "likes": 830, "comments": 41, "shares": 66, "favorites": 120, "followers": 25, "completionRate": 0.31, "avgWatchTime": 9.4 },
      "retention": [[0, 1], [1, 0.82], [3, 0.61], [8, 0.45], [15, 0.29]] },
    { "op": "write", "path": "复盘.md", "content": "# 夏日海报复盘\n\n…" }
  ]
}
```

- `post`：发布记录。新增时要有 `platform` 和 `postedAt`，FRAME 给它编号 `p1`、`p2`…；带 `id` 是修改。`export` 写发布的是哪个导出文件（`work_context` 的 exports），会记下当时的作品版本和视频时长。同一个作品发到几个平台、或换了标题封面重发，各是一条。
- `snapshot`：一条发布记录截至 `at` 的数据。
  - 数值是**截至 `at` 的累计值**。平台给的是逐日数据时，先加起来再写，或者每天写一条。
  - 时间都带时区（例如 `+08:00`）。统计时间早于发布时间会被拒绝，多半是时区写错了。
  - 标准指标：`impressions` 曝光、`views` 播放、`likes` 点赞、`comments` 评论、`shares` 分享、`favorites` 收藏、`followers` 涨粉、`clickRate` 点击率、`completionRate` 完播率、`avgWatchTime` 平均播放时长（秒）。比例写 0–1（31% 写 0.31）。平台特有的指标用中文名作键，例如 `"投币": 12`、`"2 秒跳出率": 0.25`。
  - `retention` 是观众留存曲线：`[视频第几秒, 还在看的比例]`。平台给的是视频进度百分比时先乘视频时长换算成秒；比例写 0–1，重看多的地方可以超过 1。
  - 同一条发布记录同一个 `at` 再写一次会合并（新给的指标覆盖旧的），`replace: true` 整条替换。
  - `source` 写数据来自哪个原始文件（`raw/…`）或「手动录入」；写了文件路径的原始文件算作已录入。
- `remove_post`（连同它的数据）、`remove_snapshot`（`post` + `at`）。
- `write` / `edit` / `delete` / `move`：复盘文档，`.md` 或 `.txt`，不能放在 `raw/` 里。

## 比较

总数会随时间一直涨，不同天数的数字不能直接比，所以比较时都取**发布后同一天数**的数据（`checkpoint`：`1d`、`3d`、`7d`、`14d`、`30d`）：第 7 天取第 5.6–8.4 天之间最接近的一次记录，没有就算缺。`latest` 是各自最新的数据，天数不同，只能粗看。所以录入数据时尽量覆盖发布后 1、3、7、30 天这几个时间点。

除了绝对数，更要看比例：点赞率、评论率、分享率、收藏率、转粉率（都是除以播放）、互动率、完播率、平均播放进度、3 秒留存、半程留存。流量差别很大的作品，比例才说明内容本身好不好。时长不同的视频，留存曲线按视频进度（0–100%）对齐比较（`curves: true`）。

同类作品才有可比性：用 `experience`（关联了同一个经验库）、`tags` 或 `platform` 筛选。

## 复盘的做法

1. `review_read` 看现状。有「未录入」的原始文件就逐个读出来，用 `snapshot` 录入（`source` 写文件路径）。截图里的数字看清楚再写；看不清的问用户，不要猜。
2. `reviews_compare` 和同类作品在同一天数比较：哪些指标高于中位数、哪些低。
3. 留存曲线流失明显的地方用 `preview_frames` 看那几秒的画面，结合镜头标记和字幕找原因（开头没有立刻给出看点、节奏拖沓、信息太密、转场突兀……）。回升的地方是被回看的片段，值得保留和复用。
4. 写 `复盘.md`：先写结论（表现在同类中处于什么位置），再写做得好的、问题和原因（每条都有数据或画面依据），最后写下次怎么做。
5. 把能用到同类作品上的结论整理成经验（「什么时候用、怎么做、要避免什么」，来源写作品 id 和数据，例如“3 秒留存 61%，同类中位数 48%”），征得用户同意后用 `experience_write` 写进关联的经验库。
