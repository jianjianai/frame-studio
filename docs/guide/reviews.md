# reviews：发布后的复盘

作品发到平台以后，记录它的表现、和同类作品与其他作品比较，把结论变成下一部作品的经验。

复盘资料在作品库的 `frame/reviews` 分支，每个作品一个文件夹（文件夹名是作品 id），不在作品自己的分支里：作品发布后只能查看，数据还可以一直补充。每次修改自动保存为一个版本，连接了 GitHub 时自动同步。

```
<作品 id>/
  review.json      发布记录、各次统计的数据、留存曲线（和同类作品的）、每小时数据、关键时刻、自定义分段（用工具修改，不要手写）
  复盘.md          复盘文档（可以有几篇）
  raw/<导出日期>/   平台后台导出的表格、截图等原始文件，原样保存，不能修改
```

用户在工作台左侧「复盘」里上传原始文件、查看数据和分析；首页的「复盘对比」把所有作品放在一起比较。

## 工具

- `review_import`：把 `raw/` 里平台后台导出的文件直接导入成一次数据记录，不用自己读表格。认得抖音创作者中心的作品数据导出（指标数据、留存分析的逐秒留存和同类作品、播放量和涨粉量的每小时趋势及抖音精选、流量来源和对比 7 日、涨粉脱粉与不感兴趣、观众参与度）和全部评论导出，按表格内容识别，文件名随意。同一次导出的文件放在同一个文件夹，用 `folder` 一次导入。
- `review_read`：发布记录和最新数据（和同类并列）、每小时流量、来源、留存分析、评论概况、文档和原始文件。`file` 读一个文件：xlsx / csv 读成文字表格，截图返回图片，文档返回全文。
- `review_write`：`operations` 按顺序执行，一次调用保存一个版本。
- `reviews_compare`：每条发布记录一行，取发布后同一天数的数据，和同类、和中位数比。
- 外部 AI 手上的表格、截图用 `upload_link` 的 `review: true` 上传（`path` 写 `raw/<导出日期>/<文件名>`），响应里有 sha256 可以核对。

## 读数据的口径

- **总数取同一天数比**：总数一直在涨，比较时都取发布后同一天数（`checkpoint`：`1d`、`2d`、`3d`、`7d`、`14d`、`30d`，不写时取大多数发布记录都到了的最大天数）的记录：第 7 天取第 5.6–8.4 天之间最接近的一次，没有就算缺。有每小时数据时，播放和涨粉正好算到那一天（表里标 `*`），所以导出一次就能比首 24、48、72 小时。`latest` 是各自最新的数据，天数不同，只能粗看。
- **比例在同一次记录里算**：点赞率、评论率、分享率、收藏率、不感兴趣率、涨粉率（都除以播放）、每千次播放涨粉、互动率。某个数只在更早的记录里有时，注明是第几天的。
- **和同类比**：平台给了同类作品的留存曲线时，2 秒跳出、5 秒留存、3 秒留存、半程留存、结尾留存、关键时刻还剩多少人都并列同类的值（平台自己给的 2 秒跳出、5 秒完播率照原样用，同类的从同类曲线上读）。
- **平台的完播率和留存曲线的结尾不是一个口径**（差几倍都有），比较留存看“结尾留存”和曲线，不看完播率。
- **每小时数据只看形状**：每小时播放加起来和指标数据的播放量常常对不上，总数用指标数据。时间都是北京时间。

## 留存分析

- **逐秒倍数**：这一秒的流失率（这一秒走掉的人 ÷ 当时还在的人）除以同类作品同一秒的流失率。低于 1 比同类留得住，高于 1 掉得多。`review_read` 列出倍数最高的几秒，括号里是前两秒和后两秒的倍数：只有当时或之后一两秒明显升高，才能把流失归到那一秒的画面上，要先用 `preview_frames` 看那几秒。
- **分段倍数**：一段从头到尾走掉的比例 ÷ 同类同一段走掉的比例，附“按同类走结尾多 x%”——这一段如果按同类的流失率走，看到结尾的人会多多少。分段来自作品自己：
  - 图层：visual.json 里不覆盖全片的图层（剧情短片里就是各幕）；
  - 镜头：project.ts 的镜头标记（beats）；
  - 字幕：project.ts 的字幕；
  - 歌词：配乐文件旁边的同名 `.lrc`，按 audio.json 里播放这首歌的片段换算到作品时间（剪过的歌，每句在它实际出现的位置）；
  - 用 `review_write` 的 `segments` 写的分段（例如画在代码里的镜头、歌词，或复盘时自己划的段落），同名的种类会替换自动的。
- **关键时刻**：`moment` 记下反转、兑现在第几秒。分析里给出那一刻还剩多少人（和同类比），对比表多一列“反转时还在”。
- **同一首歌的作品**：`reviews_compare` 的 `lyrics: true` 按歌曲时间逐句对齐，能把歌的影响和画面的影响分开。

## 记录数据

平台导出的文件用 `review_import`。其他来源（截图、别的平台）用 `review_write`：

```json
{
  "operations": [
    { "op": "post", "platform": "抖音", "postedAt": "2026-10-08T20:00:00+08:00", "title": "标题 #话题", "pinnedComment": "回看第 1 秒…", "goals": { "views": 1000000 } },
    { "op": "snapshot", "post": "p1", "at": "2026-10-15T20:00:00+08:00", "source": "raw/2026-10-15/后台截图.png",
      "metrics": { "views": 12034, "likes": 830, "comments": 41, "shares": 66, "favorites": 120, "followers": 25, "bounce2s": 0.3079, "retention5s": 0.4646, "avgWatchTime": 9.4 },
      "retention": [[0, 1], [1, 0.82], [3, 0.61]], "retentionBenchmark": [[0, 1], [1, 0.86], [3, 0.62]],
      "sources": [{ "name": "推荐页", "share": 0.898, "vsAccount": -0.024 }] },
    { "op": "series", "post": "p1", "key": "views", "start": "2026-10-08T20:00:00+08:00", "values": [222, 210, 208] },
    { "op": "moment", "label": "反转", "at": 28.1 },
    { "op": "segments", "kind": "镜头", "items": [{ "start": 0, "end": 3, "label": "钩子" }, { "start": 3, "end": 8, "label": "他的反应" }] },
    { "op": "write", "path": "复盘.md", "content": "# 复盘\n\n…" }
  ]
}
```

- `post`：发布记录。新增时要有 `platform` 和 `postedAt`；带 `id` 是修改。`export` 写发布的是哪个导出文件，会记下当时的作品版本和视频时长。`goals` 是目标（比例写 0–1）。同一个作品发到几个平台、或换了标题封面重发，各是一条。
- `snapshot`：一条发布记录截至 `at` 的数据，数值是**累计值**；时间都带时区，统计时间早于发布时间会被拒绝（多半是时区错了）。标准指标：`views` 播放、`likes` 点赞、`comments` 评论、`shares` 分享、`favorites` 收藏、`danmaku` 弹幕、`dislikes` 不感兴趣、`followers` 涨粉（净增，可以是负数）、`unfollows` 脱粉、`impressions` 曝光、`clickRate` 点击率、`bounce2s` 2 秒跳出、`retention5s` 5 秒留存、`completionRate` 完播率（平台）、`avgWatchTime` 平均播放时长（秒）、`watchRatio` 平均播放占比、`fanViewShare` 粉丝播放占比。比例写 0–1。平台特有的指标用中文名作键。`benchmark` 是平台给的同类值，`retentionBenchmark` 是同类作品的留存曲线。同一个 `at` 再写会合并，`replace: true` 整条替换。
- `series`：每个时段**新增**的数（不是累计），`step` 默认 3600 秒；分渠道写 `views:抖音精选`。同一指标的几次数据按时间合并，新的覆盖重叠的部分。
- `moment` / `remove_moment`、`segments`（`items` 为空删除这一种）、`remove_post`、`remove_snapshot`。
- `write` / `edit` / `delete` / `move`：复盘文档，`.md` 或 `.txt`，不能放在 `raw/` 里。

## 复盘的做法

1. `review_read` 看现状。有「未录入」的平台导出就 `review_import`；截图等读出来用 `review_write` 录入。看不清的数字问用户，不要猜。
2. `reviews_compare` 和同类作品（`experience`、`tags`、`platform` 筛选）在同一天数比较。
3. 倍数最高的几秒和倍数高的分段，用 `preview_frames` 看画面，对照前后两三秒，结合图层、镜头、歌词找原因（重复已知信息、歌词重复、要读的长文字、兑现后拖长……）。“按同类走结尾多 x%”大的段落最值得改。
4. 写 `复盘.md`：先写结论（在同类中处于什么位置），再写做得好的、问题和原因（每条都有数据或画面依据），最后写下次怎么做。
5. 能用到同类作品上的结论整理成经验（“什么时候用、怎么做、要避免什么”，来源写作品 id 和数据），征得用户同意后用 `experience_write` 写进关联的经验库。
6. 流量常有第二波：发布 3 天、7 天后提醒用户再导出一次，导入后每小时数据会接上。
