## 采用的实现及选择理由

### 1. 编辑、快照及本地 MCP 的文件 IO

将平台与本地 MCP 的耗时文件检查、编辑、历史、快照和任务校验转移至 `project-io` 工作线程。交互操作两个线程，快照独立一个线程，防止长快照占满交互通道。队列同时限制 64 个请求与 64 MiB 载荷，保留闲置 unref、失败拒绝与退出回收。

按文件身份缓存 SHA-256：包含 dev、ino、mode、nlink、size、纳秒 mtime/ctime，并在读取前后检查实际打开文件与路径。拒绝链接和非普通文件；缓存最多 65536 项。首次编辑同一素材只完整哈希一次，热编辑复用经过身份验证的摘要。保留 SHA 冲突检测、只读限制、严格校验、回滚和跨进程项目锁。

快照保留源清单检查、独立拥有的拷贝或 reflink、目标实际字节哈希及源后验检查。工作线程崩溃只清理本线程确实拥有的锁，保留恢复日志。构造和 postMessage 失败会立即拒绝当前工作，不留下迟到执行。传统同步 CLI 接口继续兼容，直接调用该接口仍是同步读取，不能把工作线程路径的收益套用到它。

### 2. PostgreSQL 锁和连接饥饿

新增延迟创建的独立锁连接池，锁池最多 12、普通池最多 12。锁作用域通过 AsyncLocalStorage 复用所持连接执行 SQL；显式事务改用 `acquireDatabaseClient`，避免在 BEGIN 后释放外层锁连接或产生重叠事务。

这一设计同时解决锁回调自身查询与共享异步任务借用普通连接的饥饿问题。LISTEN 和控制器专用连接继续使用普通池。不同键嵌套锁、脱离父调用的异步子锁和释放错误都维持连接生命周期；同键嵌套以及 hashtext 冲突保持原有 busy/409 语义，平衡 PostgreSQL 的递归锁次数。监听断线会唤醒任务等待者，关闭时回收监听与两类池。

资源取舍是每个服务进程最多 24 个 PostgreSQL 会话；锁池按需创建。部署时数据库连接预算需要包含 API、控制器和副本数。本次没有修改生产连接配置。

### 3. MCP 工具目录准备

启动时一次生成不可变目录、schema 和验证入口。tools/list 直接返回缓存目录；tools/call 只为本次所需工具注册处理器。每个请求保留自己的 server/transport，避免共享协议可变状态。

保留 Zod 默认值、refinement、鉴权、权限域、现代/兼容入口、JSON-RPC batch、错误以及原生图片和音频响应。对未经过 Fastify 解析的直接 SDK 调用保留有界 body 解析和 400/413/415 行为。消除的是重复注册及 schema 准备成本，未改变发现协议。

### 4. task_status 等待和数据库投影

在 PostgreSQL/SQLite 内部投影任务摘要，先去掉隐藏的 result.input，再将数据送回 Node。等待先订阅后查询，防止丢失恰好发生的通知；利用现有 PostgreSQL LISTEN，按 task 过滤，保留 2 秒兜底轮询和最多 1024 个等待者。

只合并并发中的读操作，不用过期状态缓存替代任务状态。超时、通知、异常和客户端断连都会清理等待；断连只结束临时等待，不取消持久任务。SQLite 以 bigint 读取事件游标，安全范围内转 number，超出安全范围用字符串保持精度。

### 5. 源码文件、搜索与上下文

新增有界源文件索引：复用时验证所有涉及目录和作用域祖先的 dev/ino/纳秒时间戳；并发最多 16，缓存最多 24 个子树、估算 32 MiB。分页只读取返回页的文件元数据；源码读取和搜索仍取当前字节并检查 SHA 与路径边界。

搜索保留文件数、字节数、正则时间及游标预算，非 UTF-8/二进制也计入已验证字节；预算不足时保留原游标位置，防止跳过文件。覆盖外部新增、删除、重命名、链接替换与内容更新。

上下文不再同步等待全仓素材引用扫描，而是项目范围后台去重刷新，并明确返回新鲜度。删除等破坏性操作先等待旧扫描，再执行强制权威刷新。缓存失效、扫描失败重试、脱离缓存的后台任务和服务关闭都有处理。素材摘要也按 bigint 文件身份验证并限制为 8192 项；不能仅凭路径认为素材未变化。

### 6. 素材构建与 SF2

普通 write:true 构建在 generateBundle 收集清单，在 writeBundle 用单个 1 MiB 缓冲拷贝大媒体，独占临时文件后原子改名。保留资源路径、文件身份、链接、输出冲突和中途变化检查，Range/HEAD 和项目 URL 合约保持一致。

SF2 拆包增加增量回调，并在工作线程逐个写入 preset 包，避免主线程一次持有全部输出包。SF2 源解析器仍加载整库，不能宣称解析内存恒定。write:false 保留上游需要的内存输出语义，这种模式仍会随素材体积增长。

### 7. Remotion 原生 bundle 与渲染会话

原生 bundle 放在项目自己的 .cache/remotion-bundles，以冻结输入和 Node、平台、架构、Remotion、React、Webpack 版本与路径等运行时身份作为键。构建原子发布，跨进程所有权/心跳、使用租约、最多 3 项 / 2 GiB 的淘汰边界共同控制复用。活跃租约不被淘汰；缓存内容、元数据损坏或链接替换均不能继续命中。

视觉会话直接使用原生路径，避免额外启动 Frame Vite/浏览器；媒体会话先准备 native，确实需要 Frame 页面或音频时再延迟初始化。关闭时取消并等待活跃原生任务后释放租约，支持并发重复关闭。冻结输入缓存只能回到所选项目的合法根目录。

大项目的 bundle 和公共媒体可能超过保留额度；此时释放最后一个租约后淘汰，下次需重建。首次原生编译仍约 13.5s。单帧 renderStill 约 0.5s 未被本次缓存解决，正式导出性能应以持续视频渲染和编码阶段单独衡量。

### 8. 历史列表

检查点 JSON 原子发布，增加绑定文件 stat 的轻量元数据 sidecar；旧格式按需迁移。列表不再读取所有历史完整内容，恢复仍读取并验证全部内容。保留旧检查点正文 ID 与文件名不必相同的兼容行为。

### 9. 公共静态资源

真正由静态服务返回的 assets/*-[hash].js/css 使用一年 immutable；HTML 和非哈希文件保持 no-cache，API 保持 no-store，私有预览继续使用私有缓存。使用当前 Fastify Reply 的 header API，覆盖实际构建资产、条件 304、缺失哈希路径回落到 HTML 和私有资源，防止错误缓存 HTML。

最新主分支已经做了 Studio 的页面拆包；本次没有将主分支的拆包成果归为新增优化。最新基准前端总输出约 1.14 MB，其中入口 229 KB、共享 UI 131 KB、创作页 419 KB，数据用于后续观察。

## 验证与修正记录

公共维护按工程要求运行了 `pnpm verify`。其 verify:core 部分通过：工程检查、平台检查、两组类型检查、83 个 Vitest、MCP 的 97 通过 / 1 跳过，以及播放器与 Studio 构建。

第一次 server 全验收在 3 GiB 容器下有 3 项失败：

- 搜索的非文本字节预算回归，已恢复原有预算与游标语义并补测。
- 同键嵌套锁错误地重入，已恢复 busy/409、平衡递归锁并补测。
- 混合多引擎完整导出的子进程被 SIGKILL，测试 cgroup 记录 OOM kill。相同主分支未优化代码在 3 GiB 条件下也无法完成该样本。没有把它记成通过。

修正后在 8 GiB / 2 CPU 容器运行 `pnpm check:platform && pnpm typecheck:platform && pnpm test:server`，完整 server 验收结果为 **265 项：259 通过、0 失败、6 跳过**，耗时约 560 秒。覆盖混合引擎 720 帧完整导出、浏览器和 CLI 导出、Remotion、音频混音与 stems、OAuth、WebSocket、作品库、账户同步、缓存失效、锁竞争、SQLite 大游标和真实 HTTP 断连取消。3 GiB 不能完成该复杂验收；此次成功不能作为低内存部署保证。

纳入 7.6.0 主分支后，平台检查、类型检查、两套构建再次通过；数据库锁、MCP 协议和静态缓存 18 项复验，以及项目 IO 与 bundle 缓存 11 项复验均全部通过。复验属于重复检查，不重复计入总数。

整套最终有效结果合计 **439 通过、7 跳过、0 未解决失败**。其中 6 个 server 跳过包括三个真实外部 CLI 执行器用例、Linux 环境下的 Windows 用例、未提供的 GeneralUser 音色库和未配置真实执行器的 MCP→Docker→CLI 全链路。另 1 个 MCP 跳过是外部许可音色样本。合成 SF2、真实浏览器渲染和媒体导出测试已运行，跳过不用于替代这些已执行的检查。
