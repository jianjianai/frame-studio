# 弱网播放 7.1.2 验收记录

## 问题与修复

旧压缩预览只准备当前位置约 0.25 秒覆盖的片段就启动，预加载转播放以及再缓冲会取消在途下载。高延迟下两个音轨相互争抢请求，导致反复停顿和重复下载。V7 直接解码路径把媒体准备迟到当作不可恢复错误。

- 压缩预览初始 6 秒，按下载耗时扩展至最多 8 秒；后续有界预取，按临近播放时间排序，并发上限 6。
- 跨音轨按 SHA-256 合并下载；预加载、播放和缓冲重用请求；跳转撤销不再需要的窗口。取消等待后不会自动播放。
- PCM 缓存按实际字节计量，上限 128 MiB；多轨/倍速时收缩预取窗口。
- 直接解码首段 4 秒、前向调度 8 秒；媒体迟到进入缓冲并冻结共同声画时钟，随后自动恢复。
- 播放器显示自动缓冲状态。原始素材、导出内容和质量不变。

## 可重复验证

`tests/mcp/preview-network.test.mjs` 在真实 Chromium 和不具备同源权限的 iframe 中，用共享传输限速器为所有音频请求合计提供 96 KiB/s（786.432 kbps），每次响应额外延迟 1800 ms。双音轨均包含独立、连续变化的音频，避免重复静音哈希掩盖网络问题。测试只限制媒体，排除模块加载和 CPU 开销干扰。

| 16 秒观测 | 基线 69127a3 | 修复版 |
| --- | ---: | ---: |
| 初次播放等待 | 4971 ms | 5097 ms |
| 实际进度推进 | 5.84 秒 | 15.95 秒 |
| 缓冲采样（100 ms 间隔） | 101/160 | 0/160 |
| 重复媒体请求 | 14 | 0 |

可用 `FRAME_NETWORK_BASELINE_REV=69127a3 node --test tests/mcp/preview-network.test.mjs` 在临时夹具内验证旧版本失败，不改开发仓库。默认运行验证当前代码。

直接音频回归使用真实 HTTP Range WAV 传输，在下载过程中人为中断 7.5 秒。修复后缓冲时钟漂移 0，随后自动继续，未报解码错误；缓存峰值约 9.98 MB。另验证冷跳转、取消启动、返回已缓存位置、原始导出、音轨控制与持久缓存。

发布门禁还捕获到父页面繁忙时 150 ms 消息握手超时导致的偶发重复下载。握手容忍时间改为 2 秒，并在弱网测试中额外注入 350 ms 父页面确认延迟：启动 5514 ms，16 秒推进 15.89 秒，0 缓冲样本、0 重复请求。未将这个出现问题的候选版本发布到生产。
