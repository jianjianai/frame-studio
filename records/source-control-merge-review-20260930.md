## 合并前发现并修复

1. **首次提交前取消暂存失败。** 新仓库暂存文件后继续编辑，再取消暂存会被 Git 拒绝。
   已在仅移除索引条目的命令中使用 `--cached --force`，工作区文件保持不变。
   原实现回归用例失败，修复后通过，并核对后续编辑仍存在。
2. **V5 撤销恢复状态未进入 SCM 只读状态。** 原分支仅检查任务状态；
   撤销在文件替换后中断时，界面仍错误地允许写操作，后端随后拒绝。
   新增 applying/failed 撤销检查及 work_undos 实时订阅；
   真实数据库回归覆盖文件替换后和两次目录重命名之间中断，并确认写操作被拒绝。
3. **自动保存覆盖独立暂存版本。** 暂存 A 后继续编辑为 B，AI／预览前自动保存会直接
   git add 并丢失索引中的 A。现在检测已暂存路径与工作区差异（含重新出现的未跟踪路径）的交集；
   检测到不同版本即拒绝自动保存，提示先提交或取消暂存，并保留 HEAD、索引和工作区。
   新增回归先证明原实现未拒绝，再验证三者均未被修改。

解决合并冲突时保留 V5 的 WebSocket 订阅生命周期与集中请求契约，
将恢复版本的 expectedRevision 加入共享契约并传递给恢复逻辑，保留提供商相关订阅。
