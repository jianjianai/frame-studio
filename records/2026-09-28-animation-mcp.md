## 实现

入口为 scripts/mcp.mjs；film mcp 在同一进程启动，以便 stdin EOF 与终止信号到达任务管理器。MCP 官方 SDK 固定为 2.1.0；server 用于服务，client 用于真实协议集成测试，均由 pnpm 更新锁文件。

scripts/mcp/server.mjs 注册 13 个工具、7 个固定参考资源、产物资源模板和编辑提示词。核心文档也可经 frame_read_reference 获取，避免依赖宿主的资源浏览 UI。

scripts/mcp/workspace.mjs 实现项目白名单、文本大小/路径限制、全文件哈希、跨进程独占锁、批量编辑、严格校验、失败恢复、成功审计。若外部修改妨碍回滚，保留备份与锁，不覆盖外部内容。原文件权限随备份与替换保留。

scripts/mcp/jobs.mjs 复用既有 render/storyboard，提供两路并发、超时、取消、断开清理、有界日志、源文件指纹和结果保存。成功 PNG 以 MCP 原生 image 返回；MP4 返回文件路径、链接和 FFprobe 报告。不属于当前会话的未完成记录显示 unobserved，不把持久化旧状态当作完成证据。

## 验证中发现并处理的问题

1. 原有三项音频单元测试仍读取已移除的 legacy audio/WAV 字段。调整为按实际音轨类型验证文件或生成模块；实际 PCM 和完整播放继续由浏览器测试负责。
2. “旧 audio 与新 audioTracks 冲突”测试原来依赖 Demo 含 audio 字段，迁移后失去前提。改为显式构造冲突数据。
3. Git 范围测试多次启动 Windows Git/Node，单次实测 5.27 秒超过默认 5 秒。仅给该测试设置 15 秒超时。
4. 两个浏览器音频夹具使用了被项目资源插件处理的 /films/ 地址，导致 404。将测试专用音频移到独立的 /**frame_test**/ 路由。
5. 循环播放测试假定 400 毫秒内能完成后段音频准备。改为最多 30 秒等待真实播放/音频/循环状态，不修改播放器行为。
6. Three.js/PixiJS 倒跳帧的 PNG 字符串比较曾失败。解码差异分别为 1280×720 RGBA 图中的 29/26 个颜色通道，每通道最大差值 1。倒跳帧使用共同的严格像素比较：尺寸一致、最大差值 1、变化通道少于 0.01%。这仍拒绝可见运动或布局差异，避免把 GPU 末位颜色舍入误报为动画状态不一致。
7. MCP 取消导出时，渲染器自身的隐藏 PCM/MP4 临时文件被普通项目文件路径规则拒绝清理。清理路径改走已验证的内部生成路径。测试改为先等待真实隐藏临时文件出现，再取消，确保覆盖该分支。
