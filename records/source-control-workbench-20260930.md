## 产品改动

原作品同步侧栏与版本管理弹窗统一为“源代码管理”持久工作面板，保留原工具选择偏好。提供变更／历史两个视图，作品菜单与左侧“版本”入口汇合；支持 `Ctrl / Cmd + Shift + G` 打开。

变更明确分为暂存区与工作区。同一文件的两种状态可以同时显示；单文件／筛选列表批量暂存、取消暂存、提交说明草稿、快捷提交与逐文件确认撤销形成完整操作链路。历史包括命名记录、提交详情、父提交文件差异、视频预览比较与追加式恢复。

新模块按需加载，无新增依赖或数据库迁移。仓库素材同步没有混入作品源代码管理。使用方式、接口与边界见 `docs/SOURCE-CONTROL.md`。

## 关键真实验收链路

真实浏览器依次验证：关闭重开保留提交草稿；查看工作区差异；暂存后继续编辑同一文件；仅提交暂存部分且不夹带新文件；历史差异不混入较晚的磁盘修改；展开并排比较与换行；手机无横向溢出和正确焦点恢复；二进制元信息；取消删除不丢文件；过期删除确认被拒绝；批量暂存并提交剩余文件；干净工作区创建命名版本；查看历史不触发恢复；删除并提交 `project.ts` 后，仍能通过历史恢复，旧提交继续存在。

Git 单测另验证中文／空格／字面路径、重命名后继续编辑、删除、无首次提交的分支、工作区与索引独立、锁获取等待但不重放写入、越界暂存阻止、硬链接／符号链接／历史链接、Git 二进制属性、LFS 指针、文本限额、真实三方冲突、脏工作区推送不自动提交、脏拉取／分叉保护、忽略文件不被覆盖、远端路径隔离与删除分支后的重新检查。

## 走查中修复的问题

1. 并排换行使用固定表格布局时，原行号列会被等宽分配。增加明确的列定义并实看展开截图确认。
2. 普通 SCM 操作后调用完整作品刷新会与紧随其后的暂存争抢锁。改为必要刷新，只有真正更换版本时重载作品；锁获取有界等待，但已经开始的写操作不会自动重试。
3. 已暂存重命名后的再次编辑不能把已经不在索引中的旧路径重新交给 `git add`。按索引状态选择路径并补回归。
4. 快进默认行为可能覆盖忽略文件，现显式使用 `--no-overwrite-ignore`，并用真实裸远端验证磁盘原件不丢失。
5. 删除作品入口后，旧状态与历史服务依赖入口存在，导致 Git 操作成功后却报失败。状态、历史与恢复改为在入口缺失时仍可定位作品 Git 分支；自动保存也覆盖已跟踪路径的删除。恢复前校验目标历史文件类型。
6. 恢复前拒绝非空暂存区，避免自动保存工作区时丢掉只存在于暂存区的中间状态。
7. 大量文件时限制列表高度并定位差异，使用 80 文件的真实 UI 回归补充验证。
