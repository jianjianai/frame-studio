# FRAME 8.1.1：共享依赖与完整音频接口修复

日期：2026-10-02（Asia/Shanghai）。8.1 功能实现记录见 `audio-preview-810-implementation-20261001.md`。

## 正式镜像发现的问题

8.1.0 提交 `fc60c9cf61e29f873aa135ae1204fd210d4b2543` 的实际 GitHub Release 构建成功。安装包、校验和、镜像 OCI revision 与源码标签核对通过。正式 app 镜像摘要为 `sha256:9c03176041c52d88579698dc2f5b55519ade95884b08fad5777de4532617574a`。

实际镜像中的 `pnpm verify:release` 返回 1：170 单元测试通过；MCP 128 项中 124 通过、3 失败、1 个可选 SoundFont 测试跳过，严格 server 阶段未执行。三个失败均为 Signalsmith `worklet.includes is not a function`。旧测试、镜像和失败证据保留；8.1.0 标记预发布，未切换生产，未改写已有标签或产物字节。

独立正式镜像对照实验定位到 Vite 文件读取范围：隔离项目的 `node_modules` 指向工作目录外的 `/opt/frame/node_modules`。普通模块路径能加载，但 `?raw` 导入在外置依赖目录不受允许时没有转成文本，返回了函数。只加入实际共享依赖目录，原始 Worklet 文本和原 PCM 断言即可通过；无需改变官方 WASM 或兼容补丁。

## 修复

- 项目执行配置与根 Vite 配置显式允许项目根和 `node_modules` 的真实目录，保持实际范围，不开放整个 `/opt` 或宿主。
- 真实浏览器回归使用 production 环境和外部共享依赖，检查 raw 导出的字符串及官方源码标记，保留现有音频质量门槛。
- 底层 Signalsmith schedule/start 支持官方的有限数值 rate，包括 0 冻结和负速缓冲倒读；便利生成器和宿主时间线仍要求正速，提前拒绝无效时长与除零。
- 对齐旧 Tone 命名空间说明及显式 compressed/high 的媒体代理规则。AI 的旧 reference 入口和新创作指南保持一致。
- 产品与公共协议版本同步为 8.1.1。

## 补丁验证

在独立正式镜像容器中覆盖本次源文件，保持 production 环境与 `/workspace/node_modules` 外置共享链接：

- `tests/mcp/audio-creative.test.mjs`：4/4 通过。
- 两套 TypeScript 检查通过。
- 0 速冻结三段输出为 660 Hz，RMS 约 0.054–0.080。
- -1 速有界缓冲倒读输出依次约 875 / 660 / 220 Hz，均为有限样本且 RMS > 0.064。
- 高层 0 / -1 / NaN 三项速率均明确拒绝；正速循环、流式缓冲、未来开始/停止、任意跳转等原断言保留并通过。
- 18 种 Tone 效果与 8 种调制切片检验通过；长 Signalsmith 切点误差约 1.49e-8，最大窗口配置约 2.24e-8。

这不是新的正式镜像全量门禁或生产上线证明。8.1.1 安装包/镜像发布后仍须核对不可变来源，在隔离环境执行完整 `pnpm verify:release`，再进行 Compose 切换、现有作品和三种模式/缓存更新/真实导出验收；最终结果另记生产记录。

## 能力边界

缓存就绪减少网络等待，浏览器仍需解码、CPU/DSP、声音生成和绘制。实时输入须先记录为项目素材才能重现跳转或正式导出。底层负速的有界缓冲倒读已验证；负速循环的环绕语义与音质没有额外承诺。本次补丁没有进行原生 Windows 安装运行或生产物理麦克风测试。
