## 发现的混乱或无用代码

1. 旧作品服务按作品创建 daemon；与“一个共享工作台”不符。本次重构为共享 service 与按 cwd/project/thread 的绑定。
2. 旧 FRAME 提供商目录、模型规格与原生选择器重复保存配置。本次退役，保留原生配置及实际账号。
3. 旧 native WebUI 与 FRAME 镜像耦合，不能独立升级。本次拆分镜像与运行时。
4. `works_result` / `works_undo` 依赖旧 AI tasks.kind 数据；T3 turns不写FRAME任务，生产旧AI任务为0。删除失效API和schema，不新增重复原生turn映射。作品Git版本恢复与原生checkpoint保留。
5. README与部署说明仍描述复制草稿、验证后应用，与唯一作品目录不符。本次同步修正。
6. `react-markdown`、`rehype-highlight`、`remark-gfm` 无平台源码引用，现存依赖有可清理空间。与本次native替换无必需关系，暂不改依赖，交由用户决定。
7. 原环境文档要求通过插件/SSH进入另一checkout，当前执行环境已是生产宿主机。本次改为明确本机checkout及一次性工具容器，避免测试错代码。

8. Windows旧工具组件为Node26，T3 locked runtime要求Node24（>=24.13.1 <25）。将工具组件明确递增至 tools-win-x64-2/Node24.21.0，保留旧缓存；官方v24.21.0 SHASUMS已确认Windowsx64资产存在，不能复用旧组件身份替换其内容。

9. 原生引用初版只将附件拼入文本，未传结构化reference，导致冻结报告没有画面revision/素材pins；历史chip点击也忽略URL。本次已发现并修复，补真实child→MessageChannel→Creation定位链与跨作品拒绝测试，原生完整回合仍须门禁验证。
10. desktop.css 的旧Windows欢迎/网页升级样式疑似没有JSX引用，与T3无关，暂保留待用户决定。原LocalAiSettings专用已退役样式已清除。

11. 旧 `work_undos` 没有剩余写入入口，仍被任务/仓库/实时订阅等查询，可能形成无效阻塞。生产预检为0；本次移除这些查询并在受控退役迁移清除空表，非空拒绝自动删除。

12. 播放器位置变化不断发送 `context.changed`，原生页面从不消费；删除无用高频推送，引用改为显式附件与发送前冻结。
13. 已定位的画面在预览revision变化后仍保留定位成功状态；现在实际provenance更新即清除标记，不自动seek新的源码版本。
14. 新作品初始化缺少共享工具链链接；现在按工作目录与核心指纹准备一次，保留作品 Git HEAD/index，不按会话复制依赖。
15. 本机启动器覆盖 HOME/USERPROFILE 会遮住已有 CLI 登录；桌面模式保留用户目录，Docker 模式继续使用持久化服务目录。
16. 原生流式响应每个分块都查询作品绑定并异步转发，增加数据库负载且可能乱序；现在连接建立时捕获不变的 project/cwd，同步过滤流式响应。
17. 完整原生页面的终端子进程未计入作品活动；补同一原生 WebSocket 的终端元数据订阅，避免恢复、删除和退出检查漏掉运行命令。
18. 原生 typed HTTP 客户端的中央 URL 规范化仍清空 pathname，使嵌入鉴权请求丢失 `/ai/works/<id>/`；真实浏览器门禁已拦截候选，补中央路径处理及实际请求 URL 回归后重新构建原生候选。
19. 网关过滤外国作品事件后用 shell 的同步消息填充所有流，违反终端等原生流类型；改为丢弃空分块并回 ACK，保留类型与背压。
20. 原生鉴权 CLI 初始化没有退出时取消和超时，会阻塞本机关闭；新增仅当前启动任务的取消与子进程清理，外部共享服务保持独立生命周期。
21. 新接入的共享 control 文件曾写入一个从未读取的 environmentId；删除冗余字段，补4个真实独立进程竞争创建、重启复用、权限及临时文件清理回归。
22. 原生 router 切换 thread 会丢失嵌入 nonce，刷新因此返回400；改用官方 root search middleware 仅在嵌入模式保留 nonce，完整页面保持原生导航。实际 pinned router 行为及完整 web 类型检查通过。
23. 原生完整 Git 工作台调用 GitHub CLI，独立容器最初漏装 gh；补进原生镜像，并在最终容器验收确认实际二进制。
