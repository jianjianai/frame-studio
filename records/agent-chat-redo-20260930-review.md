## 完成后的 Agent 产品评审

### 1. 是否一眼知道“正在做什么、为什么等待”

通过。消息按真实顺序展示，文字与工具不再被分成互不相关的两个区域。当前工具直接出现，完成步骤折叠；失败步骤自动展开，缺少结束事件时不假装成功。模型公开思考摘要、计划、读取/搜索、命令和文件变更有各自的阅读方式。

复审发现初稿同时显示问答工具、问题卡、待回答大提示条与运行状态，存在四处重复。已把有实际问题卡的成功问答工具行收起，移除重复横幅，将“回答”入口并入运行状态。等待使用问号图标，不继续旋转成“模型忙碌”。头部只保留历史、搜索、新对话、设置、关闭；通知统一放作品工具条及全局导航，不在同屏重复摆铃铛。

### 2. 是否真正能和正在运行的 Agent 互动

通过。单选、多选、自由文本、多题提交都连接持久化问题，而不是把回答当成新创作。真实 Codex 和 Claude Code 各自暂停到人类回答后，继续原轮命令，并可在随后一轮恢复同一个上游会话。

答案草稿刷新保留；另一个标签回答会同步回执；重复同请求返回原结果，其他请求不能覆盖已回答的问题。停止结束等待，不默认替用户选择。已回答内容默认压缩成一行摘要，需要时展开原题与答案。网页仍明确区分“回答当前问题”和“排队发送新的要求”。

### 3. 执行过程是否可检查，而不是装饰性状态

通过。命令显示工作目录、命令行、返回输出、实际退出码和用时。工具显示实际输入及结果。一个 Claude 消息中的多个块不会因第一段文字而丢失后面的工具；流式增量与完整快照不会重复堆叠。

文件列表来自工具返回的差异及隔离工作区 Git 检查，包含命令写入文件。展示增删行、类型和逐行差异，标明步骤差异与整轮净变更的区别。大文件、二进制和截断情况直接说明，不用虚构的完整比较遮掩。文件检查不暂存、不运行外部 diff/textconv、不跟随链接读取目标、不越过作品边界。

### 4. 完成后是否容易确认结果和继续工作

通过。最终回复、净文件清单和“查看本轮预览与修改”形成结果区域，沿用 V5 的前后版本、原引用和安全撤销，绑定该轮而非最新预览。通知点击进入对应作品、对话和轮次；较早轮次独立补取，不破坏正常历史分页游标。

## 迭代中发现并修复的具体问题

- 旧实现会打乱文字/工具顺序、多内容块丢失：改为有身份的增量时间线。
- 只有一次性 stdin 无法继续追问：改为双向协议和服务端持久化问题。
- 关闭/刷新与回答回执竞争：幂等请求、草稿和真实问题状态一起处理。
- 单页100条大差异可能形成超大响应：同时按字节分页，并让客户端/实时订阅读取 `hasMore`，不足100条不能再当作历史结束。
- 旧测试虚拟入口触发 Markdown 依赖二次优化，导致空页面：在该测试显式预优化依赖；丢确认重试两种场景已重新通过，不删掉重试断言。
- 桌面通知拒绝授权时勾选框应保持关闭：测试改为检查真实拒绝行为，而不是要求权限拒绝后仍选中。
- 新通知与历史分页合并可能用旧状态覆盖新状态：新返回的数据优先。
