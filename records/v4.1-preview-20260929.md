# 4.1 预览与工作台改进验证（2026-09-29）

基线 main 512a261；用户批准少量服务器计算换取流畅预览，并要求一起修复作品加载、WebSocket、GitHub 登录、语音引擎删除、ChatGPT MCP OAuth、后台任务弹窗和同步角标。部署要求 GHCR 镜像与 Dockge 项目内 bind mount。

## 实现

- 每轨两秒、64 kbps MP3 预览片段；内容校验、目标片段加载、有限预取、取消与共同时间轴缓冲恢复。正常导出使用原始生成器/文件。
- 可信父页持久缓存（128 MB / 2048 项 / 30 天），保持 iframe opaque sandbox；只允许内容散列对应的音频文件。
- 作品加载进度条与阶段提示；刷新预览和后台任务在顶栏，任务弹窗显示可计量进度和停止操作；同步按钮显示领先/落后/待保存数。
- `/api/ws` 承载动作和订阅，PostgreSQL NOTIFY 推送状态，断线后恢复游标，写操作不重放。兼容 HTTP action 保留供 CLI。
- gh 旧版本不支持 `--insecure-storage` 导致进程立即退出，已去除该参数并在镜像环境获得设备码/等待授权。
- 引擎配置可删除，模型和历史声音保留；删除后不因重启复活。
- ChatGPT OAuth：DCR、授权码 + S256 PKCE、明确登录与同意、限定回调和资源、一次性代码、轮换刷新令牌、撤销与过期。
- Compose 改用 `./postgres`、`./models`，迁移脚本在停止写入并备份后复制，校验内容与权限。

## 验证

WSL 原生目录 /root/frame-preview-speed-20260929，容器内运行 pnpm verify：63 单元 + 68 MCP/浏览器 + 17 服务端 = 148 项通过，0 失败、0 跳过。开启真实 SF2、PostgreSQL、Codex/Claude CLI 测试；生产模型提供商并未被调用。

进一步针对两个音轨（生成 + WAV，有 start/offset/duration/gain）、真实音频输出、分段边界、静音、倍速、远端跳转、导出原始音频、持久缓存复用、WebSocket 断线重连、弹窗和任务进度进行了浏览器测试：2/2 通过。每次音频请求额外延迟 450ms；首播 968ms、跳转 316ms，连续输出最低 RMS 0.0654。正式短片 WebM 导出成功；重新打开无新增音频请求；工作台未发出 /api/action 请求。

上述数据为受控本地测试，不能替代用户网络的实际测量。ChatGPT 真实账号侧连接需要用户在 ChatGPT 添加并完成授权，协议的成功与拒绝路径已用实际 MCP HTTP 和数据库验证。

## 线上验证

四个作品已完成轻量预览重建：156 秒三轨作品共 234 片段、3,874,338 字节，另三个作品分别约 530 KB、596 KB、596 KB。迁移后中文语音合成返回 200,444 字节，耗时 6.7 秒；测试导出文件已删除。

同一 Windows 机器使用 Chromium、禁用 HTTP 缓存的独立 AI 预览：长作品画面 4.35 秒、点击播放 1.29 秒；种子作品画面 2.70 秒、点击播放 1.07 秒。升级前长作品点击播放约 35.7 秒，种子作品 60 秒仍在缓冲。网络传输速度在前后测试中也发生变化，不能将全部差值归因于代码。

实际工作台另外测得首播 1.38 秒、冷跳到 100 秒后播放 1.50 秒；推进 15 秒内容耗时约 18.3 秒，诊断无错误。极慢或不稳定网络仍可能缓冲，并非保证全程零等待。本机测试曾遇到 TLS/实时连接失败，重新连接后 WebSocket 握手返回 101，完成测试期间无 `/api/action` 浏览器请求。

线上点击“刷新预览”后，后台弹窗收到实际中间进度 1/36，任务最终完成。桌面和移动截图已检查；顶部刷新/任务入口和模态进度显示正常。原始证据保存在本地主工作区 `.cache/frame-preview-speed-20260929/`；服务器重建报告位于 `/opt/stacks/frame/data/records/deploy410-check.json`。

另外进行了真正的浏览器页面 reload（时间重新归零，建立新的 WebSocket）：首次取 9 个音频片段，reload 后首播新增音频请求 0，播放 1.11 秒开始，无页面错误。该结果验证父页 CacheStorage 跨页面复用；独立 AI 预览页没有父页桥接，使用 HTTP/内存缓存。
