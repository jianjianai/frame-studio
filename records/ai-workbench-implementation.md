# FRAME 4 AI 工作台实施与验证

基线：db8e936，分支 codex/ai-workbench。产品契约见 docs/AI-WORKBENCH.md。

## 已实现

- 仓库/作品分页、最近打开、名称确认删除、名称即创建。
- 一作品一 Git 分支和 worktree，新作品独立根提交；本分支领先/落后/修改数、拉取/推送。AI 修改与命名版本保存到 Git，恢复追加提交，历史随分支同步。
- 仓库素材使用 `frame/materials` 分支，使用时复制进作品；稳定目录标识、哈希原件、来源/标签编辑、引用复核、未使用筛选和回收。旧未关联上传迁入默认内容仓库并保留 ID。
- 文件音轨渐进加载、Range/条件缓存、临近音轨预取、SF2 无损按乐器拆包；多轨混音、精确帧定位、缩放、选段播放、审片区间传给 AI。
- AI 多提供商、API 模型测试、官方授权与重登、独立 CLI 更新；持久对话、幂等消息、结构化事件、历史分页、重启续接、停止/重试、验证后自动应用/预览。
- 折叠导航、拖动双向布局、辅助功能弹窗、后台项目；没有源码编辑 UI。
- 环境变量密码、多 GitHub 账号、仓库创建/关联、语音模型和试听；临时导出清理、下载/上传租约、Releases 绑定导出源提交。

## 基线发现

文件音轨由 fetch(arrayBuffer) + decodeAudioData 全量下载解码后才播放；预览文件路由没有 Range 支持且全部 no-store。列表每次调用全仓扫描；AI 日志为累计文本抓取；提供商各只有一个配置；任务排他边界是整个仓库。这些机制都需要修改，而不仅是重新布局。

## 外部边界与发布

## 4.0.1 实机修正

4.0.0 生产浏览器复核发现 Pixi 的动态函数生成与沙箱 CSP 不兼容，以及窄屏时间轴挤压画面和播放控制区。公共渲染器在加载 Pixi 作品之前动态加载其无 eval 适配器，保持 CSP 和沙箱约束；手机预览维持 16:9 画幅，内容纵向滚动。预览运行时版本提升，旧预览自动重新构建。

浏览器回归改用实际 Pixi 作品，覆盖沙箱中播放与帧定位，并断言窄屏画面高度和时间轴不遮挡控制区。类型检查和该浏览器用例已通过；完整修订验证与部署结果见部署记录。
