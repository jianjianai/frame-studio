## 审核发现与修复

1. Agent 日志每批最多读取 8 MiB，旧判断会漏掉剩余不足 1 MiB 的完整事件。回归先复现失败，再修正结束判断；同时覆盖不完整行不能忙循环。
2. 首次会话订阅迟到时，切换初始化会话会清空刚输入的创作要求。保留用户已编辑的草稿；真实浏览器测试延迟初始会话响应，确认文本保留并完成原任务问答。
3. 新原生 Agent 运行时模块需要纳入执行器冻结指纹。已补全并验证每个模块的改动都会改变指纹。
4. 两个 CLI 分支存在相同名称、不同参数和不同返回值。统一使用 experience 的任务分页、bigint 游标、可恢复上传和安全文件读取。单文件 works_patch 保留 path/edits；跨文件精确替换独立为 works_patch_batch，配合 works_edit。没有以重复注册覆盖实现。
5. MCP 与 HTTP 共用工具可见性、注解和 schema；分页 help 和精确 tool_describe 均保留。works_read_lines 委托同一安全读取实现。
6. 远程明文 HTTP 需要显式 --allow-http，本机 HTTP 保持可用。下载保留服务器 sha256，并明确返回 checksumVerified，避免将自行计算的摘要当作服务器校验结果。
7. film platform 别名接入唯一 CLI。upload_abort 保持幂等。旧 durable executor 测试更新为校验 version 1 的已完成消息和命令事件，保留实际修改、构建、发布与凭据过滤断言。

real-film 分支的早期验收记录保留为历史证据，不代表本次最终候选已通过；本次以最终冻结镜像上的发布门禁为准。重复的旧 CLI doctor/read/write 包装接口未引入，统一 CLI 的 describe、通用操作和 workspace_context 提供对应工作流程。
