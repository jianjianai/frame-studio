# 工作台启动脚本修复

## 原因与修改

`启动工作台.cmd` 仍以根目录 `public/assets.json` 是否存在判断是否需要生成素材。作品迁移后，素材索引已位于各项目 `public/`，开发服务器直接汇总这些索引；根目录索引不存在是正常情况。旧启动脚本因此每次调用没有项目参数的 `pnpm assets`，被要求显式指定项目的生成器拒绝，工作台尚未启动就退出。

移除旧的公共索引检查及自动素材生成调用，保留依赖安装检查、仅本机监听、固定端口冲突报错和自动打开浏览器。README 明确普通启动读取现有素材，插画重建是手动的项目命令。

## 验证

- 使用真实浏览器访问该开发服务：首页 HTTP 200，5 个作品及全部封面加载成功；打开《风的邮差》并绘制第 5 秒画面，未出现页面异常或错误提示。
- 工程检查：5 个项目、0 错误、0 警告；类型检查、111 项单元测试、48 项 MCP 测试和生产构建通过。
- 完整 `pnpm verify` 退出码为 0；浏览器测试在独立端口 `5197` 运行，22 项全部通过，用时 3.3 分钟。本次合计 181 项测试通过。
- `git diff --check` 通过。
