# 全面重做：三道问题 / 153.6秒

## 被否决版的问题
模型并列陈列不等于讲解。慢速镜头掩盖信息不足；悬浮节点缺乏输入/结果对应；旁白空隙使音乐显得循环；大片浅色背景降低重点可读性。此次不用旧镜头、旧世界、旧旁白或旧配乐。旧版仅保留检查点供追溯，不是本版素材。

## 这版的叙事约束
主角始终是同一只橘猫与同一个机器任务。规则遇到遮挡 → 用样本和误差更新 → 组合特征与并行计算 → 学习决策 → 建立句中关联 → 下一词元训练 → 指令/反馈 → 多模态 → 核验。三道问题是「写规则」「从样本学」「预测下一词元」，不是三个互相排斥的历史阶段。日期作为行动中旁注，不停下来放章节页。

一镜只允许一个主动作和一个结论，结果出来就转场。先因后果：输入先到，输出后出现；红色误差先返回，权重才改变。不能让线条无目的地永久乱跑。移动通常0.22—0.55秒，跨尺度揭示0.65—0.9秒；主体到位后留给眼睛理解，不以持续缓慢运动假装流畅。叙事镜头按约3—5秒更新，转换动作快，说明动作允许清楚完成。禁止用总倍速加速代替剪辑。

## 视觉设计
使用紧凑的产品级三维物体与精准二维解释层，不建巨大空房间。炭黑/暖白交替，青绿为有效信息，琥珀为输入和选中项，朱红只表示失败。陶瓷橘猫、黑色运算体、金属边缘与投影产生触觉；文字对齐统一安全区。主体通常占可用画面的45%—70%。不使用旧的模型海洋、无限网格、圆球光环、服务器远景或泛化城市结尾。

36个旁白单元，36次信息推进。文字只做名称、数值、输入句子和结果，画面不能靠整段文章撑场。机制段在关字幕后仍有输入、处理、输出和失败/修正的顺序。

## 镜头反思标准（每段必须记录实际观察）
1. 不听旁白，能否指出本镜头刚刚发生的变化？
2. 主要物体是否有明确身份和空间关系，而不是装饰？
3. 运动的起止是否由信息变化驱动？有没有为了炫技而旋转？
4. 上一镜头的结论是否产生下一镜头的问题？
5. 最大元素、对比、声效和旁白重音是否指向同一件事？
6. 是否有遮挡、文字裁切、无用留白、重复表达、节奏拖尾？
如果只有「画面干净」「帧率通过」，不能写审美合格。

## 逐段方案
0—9.6 悬念：橘猫快速翻转，位置式耳朵检测失效；观众知道还是猫，机器却不确定。三问题在检测路径上快速出现，不独立做片头。
9.6—27.1 规则：耳朵与胡须被抽取成条件，AND门合拢得到猫；遮挡幕移入，耳朵条件变红，输出失败。1956日期在机器组装时出现。
27.1—48 学习：带答案样本输入，错误预测与正确标签对照；误差返回、指定连接权重改变、再次推理。随后立刻换未见样本，区别训练与检验。
48—64.1 视觉：同一猫图被扫描，边缘、局部与模式逐级组合；随后一个数据批次分配给并行计算单元。2012 AlexNet旁注，特征是教学示意。
64.1—77 决策：图像单元匹配切成棋子；三处候选被筛选/评估，选中路径后落子。结果4:1，其他候选清除，不悬浮一堆无关棋盘。
77—99 关联：词元进入一句话，代词提问产生指向猫的加权关联；放大一条关联看向量乘加，再回到组合结果。2017 Transformer旁注。
99—126 生成：候选词元竞争、东方进入空位；更多文本实例涌入训练，指令示范与反馈改变输出。2022发布旁注，接着同一猫、文字和声音在一套系统中协作。
126—138 核验：音乐断拍；一本正经的输出附上不存在的来源，核验发现断链。重要输出必须经过核实，不把概率当真理。
138—153.6 收束：规则模板、学习网络、协作通道快速装配成同一工具，起初的猫重新出现；问题由人提出，输出由人核验。音乐从悬而未决到短促终止，不泛泛拉远城市。

## 声音设计
八段重新作曲而非同一段换速度：142 BPM悬念切分；124 BPM机械脉冲；138 BPM学习碎拍；146 BPM并行推进；72 BPM棋局半拍与关键落子留白；140 BPM关联弹拨左右呼应；148 BPM生成段密集推进；风险段减法断拍；结尾118 BPM半拍和声落定。鼓点、低频、短动机、音效分轨，旁白优先。只让重要碰撞和切点配重音，不能每帧敲一下。

音色由Web Audio短采样与确定性乐谱生成；不用上一版逐样本重复扫描整份语音窗口的重CPU实现。浏览器播放和离线导出共享源时间乐谱。必须实测播放，不能用导出成功代替播放成功。
